# GunGang 서버 설정과 로비

## 설치와 폴더

Minecraft 1.20.1 / Java 17 / Forge 47.3.22 이상에서 같은 JAR를 서버와 클라이언트의 `mods`에 넣습니다. 제공된 `server_resource`는 Mohist 1.20.1-923, Forge 47.3.22, TaCZ 1.1.7-hotfix를 사용합니다. 빌드는 Forge 47.4.0을 기준으로 하며, Mohist의 다른 플러그인과 함께 실제 경기를 진행하는 검증은 별도로 필요합니다.

클라이언트에만 설치해도 기존 음향·HUD 기능을 사용할 수 있습니다. 서버에 설치하면 서버 음향 설정이 우선하며, 로비와 무기 UI는 클라이언트에도 이 모드가 있어야 표시됩니다. 모드 없는 클라이언트의 소리는 강제 변경할 수 없습니다. 싱글플레이에서는 개인 음향 설정을 사용합니다.

서버 최초 실행 시 다음 파일을 만듭니다.

```text
config/gungang/
  acoustics.json       # 서버 음향 설정
  server/
    maps/example.json       # 맵마다 개별 JSON
    weapons/01_bow.json     # 주무기마다 개별 JSON
    sub_weapons/01_sword.json # 보조무기마다 개별 JSON
    slot9.json              # 핫바 9번 기본 아이템 (null이면 지급 안 함)
  fonts/               # 클라이언트의 커스텀 TTF 폴더
  exports/             # exportitem 명령으로 저장한 실제 아이템 NBT
  result/              # 경기 종료 시 날짜·맵·플레이어 전적 TXT
```

폰트는 각 클라이언트의 `config/gungang/fonts`에 넣습니다. 서버 폰트가 클라이언트로 자동 전송되지는 않습니다. 기존 `config/fonts`의 TTF는 최초 폴더 이전 때 새 폴더로 복사하며 기존 파일을 지우거나 같은 이름을 덮어쓰지 않습니다.

서버 `acoustics.json`에는 기존 음향 옵션과 같은 키를 사용합니다. 접속·`/gungang reload` 때 설정을 전송하고, 해당 클라이언트 옵션은 잠깁니다. HUD·폰트 설정과 Minecraft 자체 마스터 음량은 개인 설정입니다. 개인 음향 설정 파일은 덮어쓰지 않고, 서버에서 나가면 다시 개인 설정으로 동작합니다. 잘못된 범위, 알 수 없는 키, 잘못된 NBT가 있으면 재로드를 거부하고 마지막 정상 설정을 유지합니다.

## 명령어

콘솔 사용 가능 여부, 실행 조건, NBT 내보내기와 클라이언트 명령까지 정리한 [전체 명령어 안내](COMMANDS.md)를 참고하세요.

| 명령어 | 권한 | 동작 |
| --- | --- | --- |
| `/gungang lobby open` | OP 2 | 로비를 켜고 모든 접속자의 UI 열기 |
| `/gungang lobby close` | OP 2 | 로비·경기 닫기, 참여 전 위치·게임 모드 복원 및 팀 해제 |
| `/gungang lobby` | 일반 | 열린 로비 UI 다시 열기 |
| `/gungang map <id>` | OP 2 | 맵 선택 |
| `/gungang random` | OP 2 | 관전자를 제외하고 팀을 무작위로 균등 배치 |
| `/gungang team ALPHA\|BRAVO\|SPECTATOR` | 일반 | 자신의 팀·관전자 선택 |
| `/gungang ready` | 일반 | 자신의 준비 상태 토글 |
| `/gungang loadout` | 일반 | 무기 UI 열기. 경기 중에만 자기 팀 스폰 구역으로 제한 |
| `/gungang stop` | OP 2 | 현재 경기 종료, 로비로 복귀 |
| `/gungang reload` | OP 2 | 설정 다시 읽기; 준비·경기 중에는 거부 |
| `/gungang exportitem <id>` | OP 2 | 손에 든 아이템의 완전한 NBT를 `exports/<id>.json`에 저장 |

UI에서 관리자는 플레이어 행을 선택한 뒤 해당 플레이어의 팀을 바꿀 수 있습니다. 일반 플레이어는 본인만 변경합니다. 새 접속자는 미배정 상태이고, 관전자 선택은 랜덤 배치 때 유지됩니다. `Red` / `Blue` 스코어보드 팀 ID는 제공된 거점 데이터팩과 호환되도록 유지하며 표시 이름은 빨간 **Team ALPHA**, 파란 **Team Bravo**입니다.

## 경기 흐름

1. 관리자가 맵을 선택하고 팀을 배치합니다. 양 팀에 최소 한 명씩 있어야 합니다.
2. 관전자를 제외한 전원이 준비하면 즉시 선택 맵의 팀별 스폰으로 이동합니다. 미배정·준비하지 않은 플레이어가 있으면 시작하지 않습니다.
3. **30초 준비 시간** 동안 팀 스폰 공간 밖으로 벗어나면 서버가 스폰으로 돌려보냅니다. 다른 차원으로 이동해도 동일합니다. 준비 시간에는 참가자의 피해를 막습니다.
4. 선택한 무기(선택이 없으면 목록의 첫 무기)를 지급하고 무기 선택 UI를 엽니다. 기본 **E**키 또는 `/gungang loadout`으로 다시 열 수 있습니다. E키는 조작 설정에서 바꿀 수 있습니다. 전투 중 스폰 밖에서는 원래 인벤토리 동작을 유지하고, 경기 밖에서는 어디서든 무기 선택창이 열립니다.
5. 30초가 끝나면 이동 제한이 해제되고 맵의 제한시간이 시작됩니다. 경기 중에도 자기 팀 스폰 공간에서만 무기를 바꿀 수 있습니다. 실제 좌표·팀·아이템 ID는 서버가 매 요청마다 검증합니다.
6. 제한시간 또는 `/gungang stop`으로 종료하면 참여 전 위치와 게임 모드로 돌아가며 경기 지급 아이템을 회수하고 교체 전에 저장한 슬롯의 아이템을 복원합니다. 기본 인벤토리 전체를 초기화하지 않습니다. 팀과 준비 상태는 해제됩니다.

사망 후 리스폰하면 팀 스폰으로 이동하고 선택한 무기를 다시 지급합니다. 실제 부활 시점은 서버의 기본 리스폰 규칙을 따르며 HUD의 고정 3초 안내와 별개입니다. 경기 중 들어온 플레이어는 관전자로 들어갑니다. 접속 종료 시 현재 로비 참여 상태를 정리하며, 서버 강제 종료 이후의 경기 복구는 제공하지 않습니다.

## 맵 JSON

멀티플레이 맵 목록은 **접속한 서버 프로세스의 config 폴더**에서 읽어 클라이언트로 전송합니다. 클라이언트의 같은 경로에 파일을 넣어도 서버 로비에는 반영되지 않습니다. 목록이 비어 있으면 서버의 `config/gungang/server/maps/*.json`에서 `enabled: true`인지 확인하고 서버 명령 `/gungang reload`를 실행하세요. 기본 예제는 비활성 상태입니다.

대기 상태에서 `/gungang lobby open` 또는 `/gungang lobby`를 실행하면 서버 설정을 다시 읽습니다. 로비에 들어온 플레이어는 팀·준비 상태를 해제하며, 관리자의 `lobby open`은 전체 인원을 미배정으로 초기화합니다. 경기 종료 시에도 팀을 해제합니다. 무기 선택창을 열거나 무기를 선택할 때에도 서버의 `server/weapons`, `server/sub_weapons`, `server/slot9.json`을 다시 읽습니다. 설정 오류가 있으면 해당 열기·선택 요청을 거부하고 오류를 안내합니다. 클라이언트는 서버가 전송한 목록과 아이템 ID만 사용합니다.

전투 진행 중에는 자기 팀 스폰 구역에서만 무기를 교체할 수 있고, 해당 구역에서 기본 액션바 위치에 `E를 눌러 무기 교체`를 표시합니다. 키를 변경하면 안내에도 실제 키가 표시됩니다. 준비 단계에서는 팀 참가자가 무기를 선택할 수 있으며 기존 스폰 이동 제한은 유지합니다. 경기 밖에서는 로비가 닫혀 있어도 팀·위치 제한 없이 E키나 `/gungang loadout`으로 교체할 수 있습니다. 경기 밖에서 고른 무기는 실제 지급되며 다음 경기의 기본 선택으로 사용합니다. 기존 슬롯의 일반 아이템은 인벤토리로 옮기고 공간이 없으면 발밑에 떨어뜨립니다.

맵마다 `config/gungang/server/maps/<파일명>.json`을 만듭니다. `id`는 중복되지 않는 영문 소문자·숫자·`_`·`-`입니다. `gameMode`는 Minecraft 게임 모드이며 `survival`, `adventure`, `creative` 중 하나입니다. 거점과 승리 판정은 모드가 처리합니다.

```json
{
  "id": "arena",
  "name": "테스트 경기장",
  "description": "좌우 대칭 경기장",
  "enabled": true,
  "timeLimitSeconds": 600,
  "gameMode": "adventure",
  "dimension": "minecraft:overworld",
  "alphaSpawn": {"x": 0.5, "y": 65, "z": 0.5, "yaw": 0, "pitch": 0},
  "bravoSpawn": {"x": 40.5, "y": 65, "z": 0.5, "yaw": 180, "pitch": 0},
  "spectatorSpawn": {"x": 20.5, "y": 80, "z": 0.5, "yaw": 0, "pitch": 30},
  "alphaArea": {"minX": -5, "minY": 64, "minZ": -5, "maxX": 5, "maxY": 72, "maxZ": 5},
  "bravoArea": {"minX": 35, "minY": 64, "minZ": -5, "maxX": 45, "maxY": 72, "maxZ": 5},
  "capture": {
    "name": "중앙 거점",
    "area": {"minX": 17, "minY": 64, "minZ": -3, "maxX": 24, "maxY": 70, "maxZ": 4},
    "winningScore": 100,
    "captureStepTicks": 2,
    "scoreIntervalTicks": 30
  },
  "onPrepare": [],
  "onStart": [],
  "onEnd": []
}
```

`alphaArea` / `bravoArea`는 3차원 직육면체이며 플레이어 몸 전체가 들어갈 공간을 지정합니다. 스폰 좌표는 공간 안에 있어야 하고 충분한 바닥과 머리 위 여유는 맵에서 직접 확보해야 합니다. 공간을 지정해도 블록이나 맵이 자동 생성되지는 않습니다. `onPrepare`, `onStart`, `onEnd`에는 서버에 존재하는 데이터팩 함수 ID를 넣습니다. 준비 시작·전투 시작·경기 종료 시 각각 한 번 실행하며 OP 2 권한으로 실행합니다.

## 무기 JSON과 TaCZ NBT

설명·사용방법의 줄바꿈은 JSON 문자열 안에 `\n`으로 입력합니다. `\n\n`은 빈 줄 하나를 넣습니다. 예: `"description": "첫 번째 줄\n두 번째 줄\n\n추가 설명"`. Windows 형식 `\r\n`과 두 번 이스케이프한 `\\n`도 표시할 때 처리합니다. JSON 문자열 내부에 Enter로 실제 개행을 넣으면 JSON 문법 오류가 나므로 이스케이프 표현을 사용하세요. 이 처리는 화면 설명에만 적용하고 `itemNbt`는 변경하지 않습니다.

게임에서 주 손 아이템을 들고 **백틱(`)** 키를 누르면 클라이언트의 전체 아이템 NBT를 클립보드에 복사합니다. 키 설정에서 변경할 수 있습니다. 서버 원본을 JSON 파일로 내보내는 방법은 `/gungang exportitem <id>`이며, [복사와 내보내기 안내](COMMANDS.md)를 참고하세요.

주무기는 `config/gungang/server/weapons/<파일명>.json`, 보조무기는 `config/gungang/server/sub_weapons/<파일명>.json`에 **무기 객체 하나씩** 저장합니다. 배열이나 `primary` / `secondary` 감싸기는 사용하지 않습니다. 각 분류는 1~64개이며 같은 분류의 `id`는 중복될 수 없습니다. 파일명 오름차순으로 UI에 표시하고 첫 무기를 준비 시작 시 기본 지급합니다. `01_`, `02_` 같은 접두사로 순서를 지정할 수 있습니다.

주무기 파일 예시 (`server/weapons/01_mk14_hamr.json`):

`category`는 주무기·보조무기 공통 문자열(최대 32자)입니다. `돌격소총`, `지정사수소총`, `권총`, `근접무기`처럼 자유롭게 지정하며 목록과 상세 설명에 표시합니다. 생략하거나 빈 문자열이면 `미분류`로 처리하므로 기존 JSON도 그대로 사용할 수 있습니다. 카테고리는 표시용이며 무기 NBT·슬롯·성능을 바꾸지 않습니다. `/gungang exportitem` 결과에도 기본 `category: "미분류"`가 포함됩니다.

```json
{
      "id": "mk14_hamr",
      "category": "지정사수소총",
      "itemNbt": "{id:\"tacz:modern_kinetic_gun\",Count:1b,tag:{GunId:\"tacz:mk14\",GunFireMode:\"SEMI\",HasBulletInBarrel:1b,GunCurrentAmmoCount:20,AttachmentSCOPE:{id:\"tacz:attachment\",Count:1b,tag:{AttachmentId:\"tacz:scope_hamr\"}}}}",
      "name": "MK14 / HAMR",
      "description": "HAMR 조준경을 장착한 지정사수 소총",
      "specs": {"damage":"서버 설정값", "accuracy":"서버 설정값", "stability":"서버 설정값", "range":"서버 설정값", "fireRate":"서버 설정값"},
      "usage": "조준 후 발사. 실제 키는 TaCZ 조작 설정을 따릅니다."
}
```

보조무기 파일 예시 (`server/sub_weapons/01_sidearm.json`):

```json
{
      "id": "sidearm",
      "category": "근접무기",
      "itemNbt": "{id:\"minecraft:iron_sword\",Count:1b}",
      "name": "보조 검",
      "description": "보조무기 예시",
      "usage": "왼손 공격 키 사용"
}
```

핫바 9번 파일 예시 (`server/slot9.json`):

```json
{
    "id": "food",
    "itemNbt": "{id:\"minecraft:cooked_beef\",Count:16b}",
    "name": "전투 식량",
    "description": "핫바 9번 기본 지급 아이템",
    "usage": "우클릭"
}
```

`itemNbt`는 `tag` 부분만이 아니라 `{id,Count,tag}`를 포함한 **전체 ItemStack SNBT 문자열**입니다. `name`은 지급된 아이템의 표시 이름을 대체하며 나머지 NBT는 유지합니다. 주무기는 핫바 1번, 보조무기는 왼손으로 지급합니다. `server/slot9.json`은 무기 객체 하나를 넣거나 파일 내용 전체를 `null`로 지정하며, 파일이 없어도 9번 아이템을 지급하지 않습니다. 주무기 스펙은 UI용 문자열이며 실제 TaCZ 피해량 등을 변경하지 않습니다. 보조무기는 `specs`가 필요 없습니다.

총과 부착물을 실제로 조립한 뒤 `/gungang exportitem my_rifle`을 실행하고, 생성된 JSON 파일을 `server/weapons` 또는 `server/sub_weapons`로 복사하면 됩니다. 내보내기는 기존 파일을 덮어쓰지 않습니다. 무기 UI는 선택 ID만 서버에 보내며, 클라이언트가 임의 NBT를 지급 요청할 수 없습니다. 지급 무기를 다른 컨테이너에 보관했다면 다시 인벤토리로 가져와야 교체할 수 있습니다.

맵은 **`config/gungang/server/maps`만 읽습니다.** 구형 `config/gungang/maps`는 읽거나 자동 복사하지 않습니다. 구형 맵을 사용하려면 필요한 파일만 직접 새 폴더로 옮기세요. 이전 버전이 이미 복사한 파일은 자동 삭제하지 않으므로 새 폴더에서 불필요한 맵을 제거하거나 `enabled: false`로 지정하세요. 서버 로그에 실제 읽은 절대 경로와 활성 맵 수를 표시합니다.

기존 `config/gungang/loadouts.json`은 최초 실행 시 새 구조로 분리하며 원본은 보존합니다. 이미 JSON이 있는 무기 분류에는 기존 무기를 섞어 넣지 않습니다. `.weapons-migrated` 표식이 있으면 다시 가져오지 않습니다. 수정 후 `/gungang reload`로 적용합니다.

## 거점·타이머·전적

`capture.area` 안에 몸이 겹치는 살아 있는 참가자를 매 틱 판정합니다. 한 팀만 있으면 매 틱 `1 / captureStepTicks`만큼 점령이 진행되며, 기본값 2에서는 0.5%씩 증가합니다. 양 팀이 함께 있거나 아무도 없으면 즉시 멈춥니다. 이미 들어온 플레이어에게만 수평 0.15블록의 퇴장 여유를 두어 경계에서 판정이 흔들리는 현상을 줄입니다. 사망·관전·차원 이동은 즉시 제외합니다. 적 점령 게이지는 두 배 속도로 중립화합니다. 완전히 점령한 팀은 자리를 비우거나 양 팀이 함께 있어도 게이지가 깎이기 전까지 30틱(정상 TPS에서 1.5초)마다 1점을 얻습니다. 기본 100점 선취 승리입니다.

보스바 제목의 Team ALPHA·점수는 빨간색, Team Bravo·점수는 파란색입니다. 가운데는 중립 시 흰색, 점령 중인 팀에 따라 빨강·파랑으로 표시합니다. 바는 기본 클라이언트 보간을 사용하고 체력바용 보간을 중복 적용하지 않습니다.

거점 범위와 그 아래 한 블록 높이에 있는 기존 양털은 완전히 점령하여 점수를 얻는 팀의 색으로 표시합니다. ALPHA 100%는 빨강, Bravo 100%는 파랑이며 부분 점령·중립화 중에는 흰색입니다. 흰색·빨간색·파란색 색유리도 동일하게 처리합니다. 준비 시작과 경기 종료 때 흰색으로 복원합니다. 다른 재질을 양털로 바꾸거나 범위 밖 블록을 변경하지 않습니다. 탐색 범위가 65,536블록을 초과하면 블록 색 변경만 생략하고 서버 로그에 이유를 남깁니다.

`timeLimitSeconds`는 0~86400초입니다. 0이면 제한 없이 경과 시간을 올려 표시하고, 양수이면 남은 시간을 내려 표시합니다. 제한시간 종료 시 점수가 높은 팀이 승리하며 동점은 무승부입니다. `capture`를 생략하면 거점 없는 시간제 경기로 사용할 수 있습니다. `/gungang stop`은 승리 팀 없이 중단 처리합니다.

타이머는 보스바 바로 아래 커스텀 HUD에 `19:24` 형식으로 표시합니다. 갈무리(Galmuri11 Bold) 폰트에 검은 외곽선과 초록 세로 그라데이션을 적용합니다. 액션바는 바닐라 위치를 사용합니다. 30초 준비 단계에는 준비 시간이 표시됩니다. 경기 시간과 개인 플레이 시간은 준비 시간을 제외하며 서버 틱 기준입니다.

경기 중 TAB과 결과 화면의 개인 통계에는 플레이어별 K/D/A·딜량만 표시합니다. 전체 경기 시간은 결과 화면 상단에 유지하며 팀별 점수는 빨강·파랑으로 구분합니다. 개인 플레이 시간은 전적 TXT에 계속 저장합니다. 인원이 많으면 TAB을 누른 채 마우스 휠로 페이지를 넘깁니다. 적 참가자에게 실제 적용될 체력 피해를 현재 체력으로 제한하여 집계하며, 팀 피해·자해·관전자 피해·흡수 체력은 딜량에서 제외합니다. 어시스트는 사망 전 10초 안에 피해를 준 다른 적 공격자에게 부여합니다. 환경 사망은 최근 10초 안의 마지막 적 공격자를 킬로 인정합니다.

종료 시 승리/무승부/중단 화면에 개인 전적과 전체 플레이 시간을 표시합니다. UTF-8 TXT는 `config/gungang/result/날짜_시각_맵ID_UUID.txt`에 저장되어 기존 기록을 덮어쓰지 않습니다. 시작·종료 날짜와 시각(서버 시간대 및 UTC 오프셋 포함), 맵 이름·ID·설명·차원·게임 모드·제한시간, 승리 팀·점수와 개인 전적을 기록합니다. 서버 `logs/latest.log`에도 `[GunGang] MATCH START / MATCH END`로 날짜·시각·맵 정보를 남깁니다. 정상 서버 종료 시 진행 중 경기는 중단 전적으로 저장하며, 프로세스 강제 종료는 저장을 보장하지 않습니다.

## 제공 서버 자료와 연결

[server-examples](server-examples/)에 실제 스폰·거점 좌표를 옮긴 3개 맵(된장타워·일히오스·사찰), 플레이어 개인 정보 없이 추출한 총기 NBT 3개, MK14/HAMR 주무기와 S&W Model 3 보조무기의 개별 JSON을 제공합니다. 무기 스펙은 추정하지 않고 편집할 자리로 남겼습니다. S&W 예제는 서버 자료의 `bf1` 총기 팩이 필요합니다.

1. `server-examples/config/gungang`의 필요한 설정을 서버의 `config/gungang`으로 복사합니다. 예제 맵은 **비활성 상태**입니다. 실제 스폰 방의 경계를 확인해 `alphaArea` / `bravoArea`를 고친 뒤 `enabled: true`로 바꾸세요. 예제 공간은 좌표 주변의 임시 범위이며 실제 벽을 분석한 결과가 아닙니다.
2. 기존 `Gungame`의 거점·타이머 실행을 비활성화하세요. 모드와 기존 게임 로직을 동시에 실행하면 보스바·시간·승리 처리가 중복됩니다. 새 연결 데이터팩은 필요 없습니다.
3. `/gungang reload`로 설정을 읽습니다. 예제의 함수 연결은 모두 빈 배열이며 모드만으로 진행됩니다.
4. 기존 커맨드블록의 시작 버튼 대신 `/gungang lobby open`을 사용합니다.

원본 `server_resource` 파일은 수정하지 않았습니다. 맵·총기 팩·커맨드블록·Mohist 플러그인까지 포함한 실제 멀티플레이 경기와 UI 배치는 최종 서버에서 확인해야 합니다.
