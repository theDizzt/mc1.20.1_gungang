# 플레이 자동 기록과 1번 봇 학습

## 현재 방식

플레이 중 행동 라벨을 입력할 필요가 없다. **녹화 모드를 한 번 켜고 평소처럼 플레이**하면, 경기마다 자동으로 기록 파일을 만들고 관측된 동작을 학습 정답으로 저장한다. 화면 영상 녹화가 아니라 서버에서 관측 가능한 게임 상태·행동의 JSONL 기록이다.

모델은 1번 봇(내부 slot 0)에만 적용한다. 학습한 모델이 없는 모드·장비 조합, 관측할 수 없는 행동, 판단이 불확실한 상황은 기존 봇 규칙으로 처리한다. 학습 완료 모델이나 성능 향상을 보장하는 단계는 아니다.

## 가장 간단한 사용법

게임 안에서 관리자 권한으로 본인이 실행한다.

```text
/gungang bot learning record on
```

- 로비에서는 녹화 대기 상태다.
- 경기가 시작되고 본인이 참가하면 새 파일에 자동 기록한다.
- 경기 종료 시 결과를 기록하고 그 파일을 닫는다.
- **녹화 모드는 계속 ON이다. 다음 경기에서 다시 새 파일을 연다.**
- 경기 도중 모드를 켜면 그 시점부터 기록한다. 이미 지난 플레이를 복원하지 않는다.
- 준비·관전·사망 대기 구간은 사람의 학습 샘플로 사용하지 않는다.
- 폭탄전은 라운드마다 새 파일을 만들지 않고 한 경기 파일을 유지한다. 라운드 사이의 행동 구간은 연결하지 않는다.
- 시연자가 잠시 접속을 끊으면 사람의 관측을 중단하고, 같은 경기로 돌아오면 새 행동 구간을 시작한다. 1번 봇 기록은 경기 종료까지 남을 수 있다.
- 녹화 모드와 시연자 UUID는 서버의 `config/gungang/bot-learning/recording-mode.json`에 저장한다. 서버 재시작 후에도 복원되며, 직접 OFF로 바꿀 때까지 다음 참가 경기를 자동 기록한다. 모델 적용 모드는 재시작 후 별도로 로드·활성화해야 한다.
- 모델 파일 쓰기나 학습은 경기 종료 시 자동 실행하지 않는다.

녹화 모드를 완전히 끄려면 다음을 실행한다. 경기 중이라면 현재 파일도 닫는다.

```text
/gungang bot learning record off
```

상태 확인:

```text
/gungang bot learning record status
```

`recordingMode=ON`과 `recording=false`이면 모드는 켜져 있지만 현재 경기 파일을 녹화하지 않는 대기 상태다. 파일 저장 오류는 `recordingError` 또는 `error`, 누락은 `dropped`에 나타난다. 파일 생성 실패 시 같은 경기에서 계속 재시도하지 않는다. 원인을 해결한 뒤 모드를 껐다 켜거나 다음 경기를 시작한다.

## 명령어 전체

녹화 모드와 모델 적용 모드는 서로 독립적이다. `learning on`은 녹화 시작 명령이 아니고, `learning off`는 녹화 중지 명령이 아니다.

| 명령어 | 기능 |
|---|---|
| `/gungang bot learning record on` | 본인을 대상으로 자동 녹화 모드 켜기 |
| `/gungang bot learning record off` | 자동 녹화 모드 끄기 + 현재 파일 닫기 |
| `/gungang bot learning record status` | 녹화 및 모델 상태 확인 |
| `/gungang bot learning record` | `record on`과 동일한 이전 명령 호환 별칭 |
| `/gungang bot learning stop` | `record off`와 동일한 이전 명령 호환 별칭 |
| `/gungang bot learning` | 전체 상태 확인 |
| `/gungang bot learning reload` | 검증 후 `policy.json` 로드·교체. 적용 모드는 유지 |
| `/gungang bot learning shadow` | 모델 보정과 행동 예측을 계산·기록하되 실제 행동에는 적용하지 않음 |
| `/gungang bot learning on` | 1번 봇에 모델 보정 적용 |
| `/gungang bot learning off` | 모델 적용 해제, 기존 규칙으로 복귀 |
| `/gungang bot learning label <행동>` | 이전 수동 학습 실험용. 기본 자동 학습에는 불필요 |

한 번에 한 사람의 시연을 기록한다. 같은 사람이 `record on`을 반복해도 진행 중인 경기 파일을 나누지 않는다. 다른 사람으로 변경하려면 먼저 `record off`를 실행한다. 모델의 `on`/`shadow` 전에 `reload`가 필요하며, 이 명령은 로비에 1번 봇을 추가하지 않는다.

## 자동으로 무엇을 배우는가

관측을 먼저 저장하고 **그 다음 10틱 동안 실제로 일어난 동작**을 정답으로 만든다. 정답의 미래 정보를 관측 입력에 섞지 않는다.

| 행동 헤드 | 자동 정답 | 현재 1번 봇에 반영되는 방식 |
|---|---|---|
| `movement` | 보였던 적에게 접근 / 거리 벌림 / 횡이동 / 정지 / 임무 방향 이동 / 기타 | 기존 돌격·엄폐·후퇴·교전·임무 행동의 선호 점수 보정 |
| `fire` | 발사 신호 또는 관측 가능한 탄약 감소 유무 | 기존 발사 조건이 맞는 상황에서 시작 시점을 최대 10틱 보류할 수 있음 |
| `reload` | 관측 가능한 재장전 상태가 새로 시작했는지 | 적이 보이지 않고 위험 지역이 아니며 탄창 65% 미만일 때 조기 장전 요청 가능 |
| `secondary` | 관측 가능한 보조무기 사용 요청 유무 | 일부 공격형 보조무기의 기존 실행 기회를 최대 10틱 보류할 수 있음 |

‘적과 거리를 벌림’은 관측된 이동 방향이다. 이를 사람이 의도한 전술적 후퇴라고 단정하지 않는다. 횡이동·정지 역시 기존 실행기에 연결하는 작은 보정이며, 키 입력이나 이동 경로를 그대로 재생하지 않는다.

발사·보조무기 사용의 YES 예측은 사선·쿨타임·효용·안전 조건을 무시하고 강제로 사용하게 하지 않는다. NO 예측도 지속적인 사용 금지가 되지 않도록 제한한다. 보조무기의 경우 다음 기존 판단 기회가 10틱보다 늦을 수 있지만, 같은 NO 예측 때문에 계속 거절되지는 않는다.

### 관측 품질 처리

- 재장전·탄약은 기존 TaCZ 공개 API를 읽기 전용으로 조회한다. 사람에게 봇 무기 실행기를 생성하거나 탄약을 보급하지 않는다.
- API를 읽을 수 없으면 모르는 상태로 표시한다. 이를 ‘재장전 안 함’이나 ‘발사 안 함’ 정답으로 만들지 않는다.
- 발사 신호는 사용 시도를 포함할 수 있어 실제 탄 발사 성공·명중과 같지 않다.
- 보조무기 정답은 사용 요청이다. 쿨타임 확정이나 파괴 후 쿨타임 갱신을 사용 성공으로 오인하지 않는다.
- 보조무기의 NO 정답은 사용 요청 경로를 관측하는 지정된 GunGang 가젯 종류에서만 생성한다. 알려지지 않은 외부 아이템은 추측하지 않는다.
- 피격·공중 이동·물속·탑승 구간은 자발적 지상 이동인지 불확실하므로 이동 정답에서 제외한다. 다른 관측 가능한 행동은 남길 수 있다.
- 사망 대기·관전·접속 공백·장비/차원 변경·한 틱에 8블록 초과 이동은 구간을 끊는다. 10틱 미만인 마지막 구간은 버린다.
- 사람의 적 관측은 64블록, 정면 120도, 시선·연막·스폰문 검사를 사용한다. 봇은 설정된 감각을 사용하므로 완전히 같은 관측 분포는 아니다.
- 숨바꼭질은 위장한 적의 실제 몸 위치를 드러내지 않는다. 본인의 원시 관측만 남기고 현재 자동 정책 학습에서는 제외한다.
- 시선, 속도, 질주·웅크림·사용 아이템, 피해 및 경기 결과도 기록한다. 현재 시선 조준, 무기 전환, 점프, 신규 무기 실행을 직접 학습·제어하는 헤드는 없다.

## 학습 명령

업데이트된 모드로 경기를 마치거나 녹화 모드를 끄고 파일 저장이 끝난 뒤 실행한다. 저장 위치는 **실행 중인 서버 기준** `config/gungang/bot-learning/recordings/session-<UUID>.jsonl`이다.

저장소 루트에서 실행하는 로컬 서버 예시:

```powershell
python scripts/train_bot_policy.py run-server/config/gungang/bot-learning/recordings --output build/bot-auto-v1.json --version auto-v1
```

기본값은 `--method auto`다. **label 명령이 없는 한 경기로도 조건을 충족하면 첫 후보를 만들 수 있다.** 모드·행동 헤드·장비 조합마다 40개 이상의 10틱 샘플과, 두 종류 이상의 행동을 각각 5개 이상 관측해야 한다. 재장전을 한 번도 하지 않았다면 재장전 모델을 만들지 않고 기존 규칙을 유지한다.

이는 최소 파일 생성 기준이며 충분한 학습 품질을 뜻하지 않는다. 데이터가 부족하면 플레이를 더 기록하면 된다. 한 경기만 있으면 독립된 검증 경기가 없다는 점도 결과에 표시한다.

여러 경기 파일이 있으면 경기 파일 전체를 단위로 학습/검증을 나눈다. 인접 프레임을 양쪽에 나누지 않는다. 열려 있는 파일, 종료 표식이 없는 파일, 누락이 보고된 파일은 기본 자동 학습에서 거절한다. 녹화 모드가 켜져 있어도 경기 종료 후 닫힌 파일만 골라 학습할 수 있다.

| 옵션 | 의미 |
|---|---|
| `--method auto` | 자동 관측 행동 학습. 기본값 |
| `--output <새 후보.json>` | 후보 출력. 기존 파일이나 파일명 `policy.json`에는 출력하지 않음 |
| `--version <이름>` | 후보 버전 식별자 |
| `--epochs <횟수>` | 반복 횟수, 기본 20, 허용 1~200 |
| `--max-rows <행 수>` | 읽기 한도, 기본 50,000. 초과 시 파일을 나누거나 한도 조정 |
| `--seed <정수>` | 학습 순서·경기 분할 난수 시드, 기본 7 |
| `--method bc` | 기존 수동 전술 라벨 기록 학습 |
| `--method sarsa --base <후보.json>` | 기존 전술 행동 헤드의 실험용 오프라인 SARSA. 자동 행동 전용 후보에는 적용 불가 |

Python 3.10 이상과 표준 라이브러리만 사용한다. GPU·외부 API·Python 추론 서버는 필요 없다. 게임 중 자동 학습하거나 모델을 자동 승격하지 않으며, 학습 시간·메모리 사용은 데이터량에 따라 달라진다.

## 후보 적용과 복귀

1. 후보 파일을 별도로 보관한다. 기존 활성 파일이 있으면 백업한다.
2. 선택한 후보를 서버의 `config/gungang/bot-learning/policy.json`으로 복사한다.
3. 게임 안에서 먼저 관찰 모드로 확인한다.

```text
/gungang bot learning reload
/gungang bot learning shadow
/gungang bot learning record on
```

4. 비교 후 실제 적용한다.

```text
/gungang bot learning on
```

5. 기존 규칙으로 즉시 복귀하려면 다음을 실행한다.

```text
/gungang bot learning off
```

이전 후보로 돌아가려면 백업 파일을 `policy.json`으로 복원한 뒤 `reload`한다. 잘못된 파일을 재로드해도 이미 로드된 모델은 유지된다.

자동 모델은 `schema=2`의 `controls`를 사용하며 이전 `schema=1` 전술 모델도 읽을 수 있다. 학습에서 충분히 관측된 주무기·보조무기 조합에만 자동 행동 헤드를 적용한다. 확률 0.7 이상이고 차순위와 차이가 0.2 이상일 때만 보정한다. 이 값은 보수적 사용 문턱이며 정확도가 보장된 신뢰도로 해석하지 않는다.

`shadow`는 `controls` 예측과 전술 보정값을 기록하지만 실제로 적용하지 않는다. `suggestion`은 보정값이 가장 큰 전술 행동이지, 별도 실행한 가상 봇의 최종 행동은 아니다.

## 기존 AI와의 연결

기존 구조는 단순 FSM이 아니라 **유틸리티 점수 판단 + 행동 트리**다.

| 영역 | 기존 코드 | 유지·확장 방식 |
|---|---|---|
| 감각 | `BotPerception` | 시야·소리·피격·제보·위험 기억 유지 |
| 전술 | `BotTactics` | 유효 행동 점수만 보정, 전체 잔차 최대 ±12 |
| 실행 | `BotActions`, `BotTree` | 검증된 행동 트리를 실행 |
| 주무기 | `BotGun`, `BotAim`, `BotRanged` | 탄도·사선·반응·조준·기존 재장전 규칙 유지 |
| 보조무기 | `BotGadgets`, `BotGadgetScore` | 쿨타임·안전·효용 규칙 뒤에 제한적 타이밍 보정 |
| 임무 | `BotObjective`, `BotBombDecision` | 임무 및 긴급 설치·해체 판단 유지 |
| 학습 | `BotLearning`, `BotDemonstration`, `BotPolicy` | 관측 구간 기록, 경량 추론, 모델 교체 |

위험 즉시 이탈, 낮은 체력, 재장전, 실패 쿨타임, 엄폐/방패 유지 규칙이 전술 보정보다 우선한다. 긴급 폭탄 판단도 유지한다. 모델은 Java 소스나 새 행동 코드를 자동으로 생성하지 않는다.

현재 자동 정책 대상은 `CONTROL`(쟁탈전), `NORMANDY`(이동점령), `ESCORT`(호위), `BOMB`(폭탄전), `DEATHMATCH`(팀 데스매치), `FREE_FOR_ALL`(개인전)이다. `PROP_HUNT`는 별도 관측·행동 체계가 필요하다.

기존 점검에서 `BotGadgets.supported()`의 장비 선택 허용 범위가 실제 실행기보다 넓은 문제가 있었다. 보이드 앵커·공중 강습 전용 실행, 손도끼 전용 투척은 별도로 보완해야 한다. 그 무기를 사람이 사용한 기록이 있어도 봇에게 없는 실행 능력이 자동으로 생기지는 않는다.

## 결과 기록과 강화학습의 현재 범위

피해·사망·경기 결과는 계속 기록한다. 기존 전술 전이 보상은 준 피해/대상 최대 체력, 받은 피해/자신 최대 체력의 음수, 사망 -1, 마지막 살아 있는 전이의 경기 승패 ±2다. 점령 기여·수레 이동·설치/해체 성공의 세밀한 보상은 아직 없다.

**새 자동 행동 모델은 관측한 행동을 학습하는 모델이다. 실수를 결과에 따라 자동으로 제거하거나 온라인 강화학습으로 개선하는 기능은 아직 아니다.** 기존 SARSA는 전술 행동 전이를 위한 것이므로, 자동 `controls`만 있는 후보를 입력하면 명확한 오류로 중단한다. 무기별 실행 결과와 행동별 전이·보상을 추가한 뒤 자동 모델의 강화학습을 연결해야 한다.

## 기록 운영과 한계

- JSONL 외곽 `schema=1`을 유지하며 자동 샘플에 `type=demonstration`, `observationVersion=2`, `targets`, 시작/종료 틱을 추가한다.
- 경기 파일은 `recording_start`로 시작하고 `recording_end`로 끝난다. 관측·이벤트·봇 전이·경기 결과 행이 함께 들어간다.
- `human` 행은 시작 관측, `demonstration` 행은 그 관측 뒤 실제 동작이다. 기본 자동 학습은 `demonstration`만 정답으로 사용한다.
- 기존 `label`은 200틱 동안 수동 전술 정답을 남기는 호환 기능이다. 자동 학습은 이를 사용하지 않는다.
- 원시 NBT 전체, 채팅, 화면 영상은 저장하지 않는다. 위치·장비·전투 이벤트는 로컬 서버 파일에 저장한다. 자동 녹화 설정 파일에는 시연자를 식별할 UUID를 저장한다.
- 기록기는 1,024행 비동기 큐와 파일당 약 100,000행 제한을 사용한다. 초과하면 서버를 대기시키지 않고 누락 수를 올린다. 누락된 파일은 다시 수집하는 편이 좋다.
- 종료 표식은 큐를 통해 쓰므로 경기 종료 후 짧은 저장 시간이 필요하다. 강제 종료·디스크 오류 시 마지막 행은 유실될 수 있다.
- 장기간 녹화 모드를 켜면 경기마다 파일이 누적된다. 학습에 사용한 파일의 보관·정리는 운영자가 관리한다.

## 추가 작업 우선순위

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 자동 녹화·학습 왕복 검증 | 로비 대기 → 경기 A 기록 → 종료 → 경기 B 새 파일 → 모드 OFF 후 기록 없음 확인 |
| 2 | 실제 무기 사용 결과와 지원표 보강 | 사용 요청/성공/실패 구분, 외부 무기 관측 가능 여부 명시, 장비 선택과 실행기 일치 |
| 3 | 누락 실행기 구현 | 보이드 앵커·공중 강습·손도끼 투척 등을 봇이 실제로 사용할 수 있음 |
| 4 | 한 모드에서 모델 비교 | 같은 맵·장비·난이도로 규칙/후보의 임무 기여·위험 사망·사용 실패·틱 비용 비교 |
| 5 | 모드별 기여 보상 및 자동 행동 전이 | 점령·수레·설치/해체와 무기별 결과를 보상으로 연결, 반복 행동으로 보상만 얻는 상황 방지 |
| 6 | 조준·장비 전환·장기 전술 확장 | 추가 행동을 관측하고 안전한 실행기에 연결, 모르는 의도는 단정하지 않음 |
| 7 | 숨바꼭질 전용 정책 | 위장 정보 누출 없이 탐색/숨기 관측·행동·보상을 별도로 구현 |
| 8 | 별도 연습 환경의 온라인 강화학습 | 경기 초기화·행동 유효성·탐험 범위·정책 버전·평가·롤백 마련 |

당장 수동 라벨을 더 붙일 필요는 없다. 우선 한 모드의 정상 플레이를 여러 경기 기록하고, 자동 데이터 품질과 경기별 비교를 확인하는 것이 좋다.

## 검증 상태와 사용자가 실행할 검사

이번 업데이트에서는 빌드·테스트·실제 학습을 실행하지 않았다. 자동 관측 정답, 알 수 없는 입력 제외, 모드/장비 범위, 경기 단위 검증 분할에 대한 테스트 코드는 추가했다. 이전 작업 환경에서는 Python 실행 파일이 PATH에 없어 실행 경로 확인도 필요했다.

```powershell
.\gradlew.bat test --tests '*BotPolicyTest' --tests '*BotDemonstrationTest' --tests '*BotTacticsTest'
python scripts/test_bot_policy.py
```

실플레이에서는 녹화 모드의 경기 간 유지, 경기마다 파일 분리, 중간 OFF, 재접속·관전·사망·라운드 경계, 모델 오류 시 복귀, 2번 이후 봇의 행동 불변을 확인한다. 저장된 행동의 일치율만으로 승률 향상을 판단하지 않는다.
