# 봇 학습 사전작업

현재 구현은 **플레이 기록 수집과 작은 잔차 정책(residual policy)의 실험 기반**이다. 학습 완료된 모델이나 성능 향상을 포함하지 않는다. 기본값은 `off`이며, 모델 판단은 봇 **1번(내부 slot 0)** 에만 적용한다. 1번이 없는 경기에서 다른 봇을 대신 선택하지 않는다.

## 기존 행동 점검

| 영역 | 현재 구현 | 학습 시 주의점 |
|---|---|---|
| 감각 | `BotPerception`: 시야·소리·피격·아군 제보·스캔·위험 기억 | 서버가 아는 숨은 적 위치를 모델 입력에 넣으면 안 됨 |
| 의사결정 | `BotTactics`: 유틸리티 점수, 행동 유지 시간, 실패 쿨타임 | 단순 FSM이 아님. 모델이 점수 보정에 참여하기 좋은 지점 |
| 실행 | `BotActions` + `BotTree`: 엄폐·추적·임무 등의 행동 트리 | 모델이 없는 이동 기술을 만들어 내지는 못함 |
| 주무기 | `BotCombatProfile`, `BotAim`, `BotGun`, `BotRanged` | 조준 반응·탄도·재장전·사선 검사는 유지 |
| 장비 선택 | `BotLoadoutChoice`: 최근 생존·피해 성과로 다음 장비 선택 | 현재 모델은 이 선택기를 대체하지 않음 |
| 보조무기 | `BotGadgetScore` + `BotGadgets`: 효용·쿨타임·사용 처리 | 사용 가능한 장비 판정이 실제 실행기보다 넓음 |
| 위험 | `BotPerception`/`BotMovement`/`BotTactics.EVADE` | 즉시 이탈은 학습 점수보다 항상 우선 |
| 게임모드 | `BotObjective`, 폭탄 긴급 판단, 별도 `BotPropHunt` | 목표 점수·해체 마감 규칙은 학습보다 우선 |

특히 `BotGadgets.supported()`는 폭탄 외 대부분의 아이템을 받아들이지만, 실행 switch에는 `void_anchor`, `air_assault` 등의 전용 처리가 없다. 손도끼도 일반 근접무기 판정과 전용 투척 실행 지원을 별도로 검토해야 한다. **선택 가능 = 능숙하게 사용 가능이 아니다.** 이번에는 이 동작을 임의로 구현하지 않고 사용 관측을 수집할 기반을 추가했다. 모델이 이를 스스로 해결한다고 가정하면 안 된다.

## 권장 구조와 구현 범위

```text
플레이 시연 + 명시적 행동 라벨 ── CPU 모방학습 ── 후보 JSON
                                                     │
기존 감각 → 기존 행동 점수 + 모델 보정(최대 ±12) → 기존 행동 트리
                ↑                                     │
       위험/쿨타임/실패/엄폐 규칙                  1번 봇 결과 기록
                                                      │
                             실험용 오프라인 SARSA → 다음 후보 JSON
```

모델은 기존 행동의 선택 경향을 갱신한다. Java 소스나 상태 전이 코드를 자동 수정하지 않는다. 새 기술(예: 손도끼 투척, 앵커 설치 후 끌어오기 연계)은 실행기와 유효 조건을 사람이 추가한 뒤 모델의 행동 공간을 확장한다.

- 런타임: 모드별 선형 모델 + `12*tanh(score)`. GPU, Python 서버, ONNX, 외부 API가 필요 없다.
- 추론: 10틱마다 한 번, 장비/팀/모드 변경 시 즉시 갱신. 서버 틱에서 학습·파일 읽기를 하지 않는다.
- 기존 점수가 양수인 행동만 보정한다. 위험 즉시 이탈, 엄폐/방패 유지, 체력 35% 미만, 재장전 중, 탄창 15% 미만, 실패 쿨타임은 기존 규칙을 따른다.
- 폭탄 설치·해체의 긴급 강제 판단은 모델 선택 이후에도 그대로 적용된다.
- 모델이 없는 모드는 기존 AI로 동작한다. 모델 파일 오류 시 기존에 로드된 모델은 유지된다. `off`는 즉시 규칙 판단으로 복귀한다.
- `shadow`는 기존 행동에 영향을 주지 않고 보정값을 계산한다. `suggestion`은 **보정값이 가장 큰 행동**이지 전체 규칙을 실행한 가상의 최종 행동은 아니다.

## 모드 범위

| 모델 키 | 대상 | 초기 데이터 수집 기준 |
|---|---|---|
| `CONTROL` | 쟁탈전 | 진입·거점 유지·재탈환·회복 이탈 |
| `NORMANDY` | 이동점령 | 공격/수비를 구분한 거점 진입·방어 |
| `ESCORT` | 호위 | 수레 호위·저지·엄폐 후 복귀 |
| `BOMB` | 폭탄전 | 설치/해체 접근·엄호·생존; 긴급 타이머 판단은 기존 규칙 |
| `DEATHMATCH` | 팀 데스매치 | 교전·엄폐·합류·추적 |
| `FREE_FOR_ALL` | 개인전 | 교전·거리 유지·위험 이탈 |
| `PROP_HUNT` | 숨바꼭질 | 사람의 원시 관측만 기록. 별도 행동 체계이므로 현재 정책/훈련에서 제외 |

모드별 시연이 없는 상태에서 다른 모드 모델을 대신 적용하지 않는다. 모델 입력은 현재 체력, 보이는 적 수/거리, 최근 피격, 불붙음(`hazard`), 임무 존재/내부/상태, 주무기·보조무기 ID와 팀이다. 지형 전체, 적의 실제 비가시 위치, 미래 결과는 입력에 포함하지 않는다. 봇의 상세 위험 인식은 별도 `knownHazard`에 저장하고 강제 회피에 사용한다.

사람의 관측은 64블록·정면 120도·시선/연막/스폰문 검사로 추출한다. 봇은 설정된 감각을 사용하므로 두 관측 분포가 완전히 같지는 않다. 현재 모델은 짧은 특징 벡터를 사용하는 시작점이며, 장기 계획·정밀 조준·새 경로 생성 모델은 아니다.

숨바꼭질에서는 위장한 플레이어의 실제 몸 위치로 적 수/거리를 계산하지 않는다. 사람 본인의 움직임·장비 기록만 남기며, 전용 관측 어댑터를 추가하기 전에는 전술 학습에 사용하지 않는다.

## 사용 순서

명령은 관리자 권한이 필요하다. 플레이할 사람 본인이 게임 안에서 시작한다. 게임모드/장비를 선택하고, 필요한 경우 로비에 1번 봇을 추가한다.

```text
/gungang bot learning record
/gungang bot learning label OBJECTIVE
```

`label`은 다음 10초의 시연에만 적용된다. 실제 그 행동을 수행하는 동안 사용한다. 다른 의도로 바뀌면 즉시 새 라벨을 지정하거나 10초 만료를 기다린다. 가능한 라벨은 `ENGAGE PUSH COVER RETREAT REGROUP SUPPORT HEAL INVESTIGATE RALLY OBJECTIVE PATROL EVADE`. `EVADE` 시연은 남지만 강제 회피 동작은 학습 대상에서 제외한다. 라벨 없는 기록의 의도를 임의 추정하지 않는다.

```text
/gungang bot learning stop
/gungang bot learning
```

저장 위치는 실행 중인 서버의 `config/gungang/bot-learning/recordings/session-<UUID>.jsonl`이다. `stop` 후 비동기 기록기가 큐를 비우는 짧은 시간이 필요하다. 상태 명령으로 파일·저장 행 수·누락 행 수·I/O 오류를 확인한다. 기록자의 접속 종료 및 서버 종료 시 기록을 닫는다. 재시작하면 정책 모드는 다시 `off`이다.

여러 번 기록을 시작/종료해 세션 파일을 나눠 모드별로 수집한다. 처음에는 한 모드, 적은 무기 조합으로 시작하는 것이 좋다. 라벨 종류가 최소 두 가지이고 학습 분할에 40행 이상 있어야 후보가 생성된다. 이것은 파일 생성 최소 조건이며 충분한 데이터 품질을 의미하지 않는다.

서버를 끄거나 플레이하지 않는 동안 Python 표준 라이브러리만으로 학습한다. 아래 경로는 이 저장소의 로컬 서버 예시다.

```powershell
python scripts/train_bot_policy.py run-server/config/gungang/bot-learning/recordings --output build/bot-bc-v1.json --version bc-v1
```

출력은 후보 파일이다. 기록 세션 전체를 기준으로 검증 분할하고, 라벨 일치율을 출력한다. 세션이 하나뿐이면 검증 일치율은 없다. 이 수치는 승률이 아니며, 무작위 프레임 분할로 성능을 부풀리지 않는다. 기본 최대 읽기 행 수는 50,000, 반복 횟수는 20이다. `--max-rows`, `--epochs`로 조정할 수 있다. 외부 라이브러리 설치는 필요 없다.

검토한 후보를 서버의 `config/gungang/bot-learning/policy.json`으로 복사한다. 기존 파일은 별도 이름으로 보관하면 롤백할 수 있다.

```text
/gungang bot learning reload
/gungang bot learning shadow
/gungang bot learning record
```

규칙 AI와 모델 보정 기록을 비교한 뒤 적용한다.

```text
/gungang bot learning on
```

적용 대상은 1번 봇만이다. 롤백은 `learning off`, 또는 이전 `policy.json` 복원 후 `learning reload`이다. 후보 생성 스크립트는 활성 `policy.json`이나 기존 후보를 덮어쓰지 않는다. 재로드도 완전히 검증한 후보만 교체한다.

## 제한적 강화학습 실험

1번 봇의 전이 기록은 `(state, action, reward, next, terminal)` 구조이며 실제 실행기에 전달된 행동을 기록한다. 행동이 같으면 10틱 간격, 행동이 바뀌면 즉시 샘플을 남긴다. 제거·기록 종료·모델 변경·40틱 초과 관측 공백은 학습 시 이어 붙이지 않는다.

현재 보상은 준 피해/대상 최대 체력, 받은 피해/자신 최대 체력의 음수, 사망 -1, 마지막 살아 있는 전이의 경기 승패 ±2다. 경기 결과는 별도 행에도 남긴다. **점령 기여·설치/해체 성공·수레 이동량의 세밀한 보상은 아직 없다.** 죽어서 마지막 전이가 없는 봇에게 결과 보상을 소급하지 않는다. 다음 단계에서는 모드별 기여 보상을 실제 이벤트에서 추가해야 한다.

```powershell
python scripts/train_bot_policy.py run-server/config/gungang/bot-learning/recordings --method sarsa --base build/bot-bc-v1.json --output build/bot-sarsa-v2.json --version sarsa-v2
```

이 명령은 관측된 다음 행동을 사용하는 **실험용 오프라인 SARSA**를 수행한다. 미관측 행동의 최대 Q를 사용하지 않고, 모방학습 후보에서 존재하는 행동만 조정하며, 각 가중치 변화는 기준 모델 대비 ±0.15로 제한한다. 모방 점수를 초기값으로 사용하므로 정확히 보정된 Q함수로 해석하지 않는다. 관측된 행동 분포의 편향을 해결하거나 성능 향상을 보장하는 알고리즘은 아니다. 자동 탐험·실시간 재학습·자동 모델 승격은 구현하지 않았다.

실제 온라인 강화학습을 확장하려면 별도 연습 경기에서 환경 초기화, 행동 유효성 마스크, 단계별 보상, 정책 버전 고정, 이전 정책 대비 평가를 먼저 마련해야 한다. 연습에 사용한 맵/시연과 평가용 맵/시연을 분리한다.

## 기록 계약과 무기 사용 확장

- 모든 행은 `schema=1`, 증가하는 `sequence`를 가진다. `human`, `bot`, `event`, `damage`, `damage_dealt`, `transition`, `match_end`를 구분한다.
- 사람/봇 관측에는 모드·맵·위치·시선·무기 정보·임무 거리/행동이 들어간다. 사람은 속도·질주·웅크림·아이템 사용 여부·보조무기 쿨타임도 기록한다. 봇은 탄창 비율·재장전·보조 사용 상태를 기록한다.
- `shot_cue`는 기존 봇 청각 훅의 발사 신호다. 모든 무기의 실제 탄 발사 성공을 보증하지 않는다. 봇 총기의 `NO_AMMO` 시도도 포함될 수 있다.
- 사람의 `secondary_cooldown_commit`은 쿨타임 확정 시점이다. 파괴 후 쿨타임 갱신 등도 포함하므로 곧바로 사용 성공 라벨로 취급하지 않는다. 봇의 `secondary:<kind>`는 해당 실행기가 성공을 반환한 시점이다. 지속 방패/자동 생명유지/특수 분기의 모든 효과 시작을 포괄하지 않는다.
- 원시 NBT 전체, 화면 영상, 채팅 내용은 기록하지 않는다. 무기는 지급된 `GunGangLearningWeaponId`를 사용하고, 태그가 없으면 아이템 레지스트리 ID로 대체한다.
- 파일 쓰기는 1,024행 제한 비동기 큐, 파일당 최대 약 100,000행이다. 넘치면 서버를 기다리게 하지 않고 행을 버리며 `dropped`에 표시한다. 상세 분석에는 누락이 없는 세션을 우선 사용한다. 세션 파일의 누적 용량은 운영자가 관리한다.

무기 사용 모델은 후속 단계에서 별도 행동 헤드로 분리한다. 예: `PRIMARY_FIRE`, `RELOAD`, `SWITCH_SECONDARY`, `USE_SECONDARY`, `HOLD_SECONDARY`. 우선 실제 성공/실패, 남은 탄약/장전, 보조무기 준비 상태, 투척 예상 충돌점, 아군 피격 위험을 공통 형식으로 추가해야 한다. 현재 학습기는 고수준 전술 행동만 학습하며, 이 원시 무기 이벤트를 전술 정답으로 오용하지 않는다.

위험 회피도 새로운 지형 위험 특징과 안전한 이동 실행기가 먼저 필요하다. 이번 모델이 담당하는 부분은 기존 엄폐·후퇴·임무 행동 중 무엇을 더 선호할지이며, 기존 위험 이탈 규칙을 학습으로 약화시키지 않는다.

## 검증할 항목

이번 변경에서는 사용자 요청에 따라 빌드·테스트·실제 학습을 실행하지 않았다. 검증용 테스트 코드는 추가했다.

현재 작업 환경의 PATH에는 `python`/`py`/`python3`가 없어 Python 구문 검사도 완료하지 못했다. 학습 시 Python 3.10 이상 실행 경로를 준비해야 한다. 서버 종료 시 기록기는 최대 1.5초 동안 큐를 비우지만, 강제 종료나 디스크 정지는 마지막 일부 행의 저장을 보장하지 않는다.

```powershell
.\gradlew.bat test --tests '*BotPolicyTest' --tests '*BotTacticsTest'
```
