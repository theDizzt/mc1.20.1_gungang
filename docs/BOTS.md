# AI 봇

[문서 안내](../README.md) · [서버 운영](SERVER.md) · [명령어](COMMANDS.md)

서버 내부에서 동작하는 **규칙 기반 봇을 최대 4명**까지 경기에 넣을 수 있습니다. 팀 데스매치·쟁탈전·개인전·이동점령·호위·폭탄전·숨바꼭질을 모두 지원하며, 봇은 각 모드의 규칙과 임무를 인식해 움직입니다. 별도 AI 모델, 외부 API, GPU, 플레이 기록 수집이나 학습 과정이 없습니다. 서버와 클라이언트에 같은 새 JAR를 설치해야 합니다.

## 설치와 준비

| 항목 | 준비할 내용 |
| --- | --- |
| 기본 환경 | Java 17, Minecraft 1.20.1, 이 모드와 호환되는 Forge 환경 |
| 모드 설치 | 서버와 접속하는 클라이언트 모두 같은 버전의 GunGang JAR 설치 |
| 업데이트 | 서버와 게임을 종료하고 기존 GunGang JAR를 새 파일로 교체. 같은 모드의 구버전·신버전을 함께 넣지 않음 |
| 관리자 | 봇 명령어와 로비 봇 조작은 OP 권한 레벨 2 이상 필요 |
| 맵 | 로비에서 선택 가능한 활성 맵, 실제 이동 가능한 ALPHA·BRAVO 스폰과 바닥 |
| 무기 | 서버 주무기 목록에 등록된 TaCZ 총기 또는 바닐라 활 |
| 총기 사용 | 서버와 클라이언트의 TaCZ 및 해당 총기 팩을 맞춤. GunGang JAR에 TaCZ가 포함되지는 않음 |

처음부터 복층이나 점프 구간이 많은 맵을 사용하기보다, 서로 걸어서 접근할 수 있는 작은 맵에서 먼저 확인하세요. 맵·주무기 등록은 [데이터 등록 안내](DATA.md), 전체 서버 설치 과정은 [서버 운영 안내](SERVER.md)를 참고하세요.

봇 기능은 최초 생성 시 **OFF**입니다. 기존 서버에 업데이트했다면 이미 저장된 `bot.json`의 값이 적용됩니다.

## 처음 실행: 사람 한 명과 봇 한 명

관리자(OP 2) 또는 서버 콘솔에서 설정합니다. 기본값은 **OFF**입니다.

```mcfunction
/gungang bot preset low
/gungang bot difficulty normal
/gungang bot team AUTO
/gungang bot weapon auto
/gungang bot on
```

게임 안에서는 위처럼 `/`를 붙입니다. 서버 콘솔에서는 `gungang bot on`처럼 앞의 `/`를 생략합니다. 명령어 인자는 TAB으로 자동 완성할 수 있습니다.

1. 관리자 계정으로 서버에 접속합니다.
2. 위 명령으로 저부하 프리셋, 보통 난이도, 자동 팀·무기를 설정하고 봇 사용을 허용합니다.
3. `/gungang lobby open`으로 로비를 엽니다. 이미 열린 로비를 다시 보려면 `/gungang lobby`를 사용합니다.
4. **맵 선택** 탭에서 사용할 맵을 선택하고 모드를 선택합니다. 처음에는 **팀 데스매치**로 확인하는 것을 권장합니다. 모든 모드에 봇을 넣을 수 있습니다.
5. **플레이어 / 팀** 탭에서 본인 이름을 **ALPHA** 칸으로 끌어 놓거나, 본인을 선택하고 **Team ALPHA**를 누릅니다. 혼자 테스트할 때 본인이 관전자나 미배정이면 참가할 수 없습니다.
6. 오른쪽 아래 **봇 추가 0/4**를 누릅니다. 자동 팀 설정에서는 `Rookie`가 BRAVO에 표시됩니다. 더 누르면 봇이 한 명씩 늘어납니다.
7. 본인의 **준비 완료**를 누릅니다. 다른 사람이 있다면 관전자를 제외한 참가자도 모두 팀 배정과 준비를 마쳐야 합니다.
8. 일반 팀데스매치는 30초 준비 후 시작합니다. 봇은 준비 중 공격하지 않고 경기 시작 후 이동·탐색·사격합니다. 준비 중에도 움직일 수 있는 방어팀(이동점령·호위·폭탄전)의 봇은 준비 시간에 임무 위치로 미리 이동합니다.
9. `/gungang bot status`로 참가 상태를 확인합니다. 중단하려면 `/gungang bot off`를 사용합니다.

관리자는 준비 상태와 관계없이 `/gungang forcestart`로 시작할 수도 있습니다. 이 명령도 먼저 로비를 열고 맵과 사람의 참가 팀을 정해야 합니다. 봇만 추가하고 사람은 전부 미배정인 상태로 시작하는 용도는 아닙니다.

## 로비 버튼·드래그와 팀 배정

로비에서 모드와 맵을 선택한 다음 **플레이어 / 팀 탭 오른쪽 아래의 `봇 추가 n/4`**를 누릅니다(OP 2). 누를 때마다 봇이 한 명씩 예약되어 팀 명단에 준비 상태로 표시됩니다. 팀 인원이나 명단에서 누구를 선택했는지와 관계없이 최대 4명까지 추가할 수 있습니다. 봇마다 이름·스킨이 따로 있어 `Rookie`, `Rookie 2`처럼 구분됩니다. 이름 앞에 `[BOT]` 같은 접두사는 붙지 않으며, 로비 명단에서는 봇 행을 선택했을 때 `봇 제거` 버튼이 켜지는 것으로 구분할 수 있습니다. 사람의 팀을 배정하고 준비하거나 `/gungang forcestart`를 실행합니다.

`on`은 봇 사용을 허용하는 관리자 스위치이며 자동으로 참가시키지 않습니다. 로비에서 추가한 봇만 경기 준비 시 생성되고 경기 시작 후 행동합니다. 봇 제거는 참가만 취소하며 기능 스위치는 켜진 상태로 유지합니다. 추가·제거·팀 변경 시 사람들의 준비 상태를 해제합니다. 경기 중 추가나 팀 재배치는 지원하지 않습니다. 참가 예약과 봇별 팀 지정은 로비를 닫거나 서버를 재시작하면 초기화됩니다.

| 버튼 표시 | 의미와 조작 |
| --- | --- |
| `봇 사용 꺼짐` | 서버의 전체 기능이 OFF. 버튼을 누를 수 없으며 관리자가 `/gungang bot on`을 먼저 실행해야 함 |
| `봇 추가 n/4` | 다음 봇 한 명을 예약. 실제 엔티티는 경기 준비 때 생성. 선택 상태·팀 인원과 무관 |
| `봇 4/4` | 최대 인원. 더 추가할 수 없음 |
| `봇 제거` | 명단에서 봇 행을 선택하면 켜짐. 그 봇의 참가 예약만 취소 |

일반 플레이어는 버튼을 볼 수 있어도 조작할 수 없습니다. 준비 단계나 경기 중에도 로비 추가·제거·팀 변경 요청은 거부됩니다. 경기 중 봇을 없애려면 관리자 명령 `/gungang bot off`를 사용하세요.

### 드래그로 팀 옮기기

**플레이어 / 팀** 탭에서 이름을 끌어 ALPHA, BRAVO, 미배정/관전자 칸 중 하나에 놓으면 팀이 바뀝니다. 끄는 동안 이름이 커서를 따라오고, 놓을 수 있는 칸은 초록색, 놓을 수 없는 칸은 빨간색으로 표시됩니다.

| 대상 | 관리자(OP 2) | 일반 플레이어 |
| --- | --- | --- |
| 자기 이름 | 이동 가능 | 이동 가능 |
| 다른 플레이어 | 이동 가능 | 불가 |
| 봇 | ALPHA·BRAVO 사이만 이동 가능. 관전자 칸에는 놓을 수 없음 | 불가 |

드래그는 로비 단계에서만 동작합니다. 서버도 같은 권한 규칙으로 요청을 다시 확인합니다. 기존처럼 이름을 선택하고 **Team ALPHA / Team BRAVO / 관전자** 버튼을 눌러도 됩니다.

### 자동 배정과 직접 배정

`AUTO`는 **사람 수와 앞 번호 봇들의 팀**을 함께 세어 인원이 적은 팀을 고릅니다. 양 팀 인원이 같으면 BRAVO를 선택합니다. 예를 들어 사람이 ALPHA 2명·BRAVO 0명일 때 봇을 4명 추가하면 1~3번 봇은 BRAVO(3번은 2 대 2 동률이라 BRAVO), 4번 봇은 ALPHA로 들어가 4 대 4가 됩니다.

로비에서 사람이 팀을 옮기면 자동 배정된 봇의 표시도 달라질 수 있으며, 실제 참가 팀은 경기 준비 시 결정됩니다. 경기 도중 사람이 들어오거나 나가도 봇을 자동으로 이동·교체하지 않습니다.

특정 봇의 팀을 직접 정하려면 그 봇의 이름을 원하는 팀 칸으로 끌어 놓거나, 봇 행을 선택하고 **Team ALPHA** / **Team BRAVO**를 누릅니다. 이 지정은 그 봇에만 적용되며 로비가 닫히면 초기화됩니다. 자동 배정된 봇이 들어갈 기본 팀은 다음 명령으로 정합니다(경기 밖).

```mcfunction
/gungang bot team AUTO
/gungang bot team BRAVO
```

봇은 준비 버튼을 직접 누를 필요가 없으며 명단에 `READY`로 표시됩니다. 봇의 `READY` 표시가 사람들의 준비 조건을 대신하지는 않습니다. 봇을 추가·제거하거나 팀을 바꾼 뒤에는 사람도 다시 준비해야 합니다.

### 제거, 전체 OFF, 경기 종료의 차이

| 작업 | 봇 참가 상태 | 설정과 경기 점수 |
| --- | --- | --- |
| 로비 `봇 제거` | 선택한 봇의 참가 예약만 해제 | 다른 봇과 전체 기능은 유지 |
| `/gungang bot off` | 모든 예약 해제, 생성된 봇·남은 봇 투사체 즉시 제거 | OFF 저장, 이미 기록된 점수 유지 |
| 경기 종료 | 월드의 봇 엔티티와 봇이 설치한 지뢰·방벽·베어트랩 제거 | 예약은 같은 열린 로비에서 유지 가능, 새 경기는 새 점수로 시작 |
| `/gungang lobby close` | 모든 참가 예약 해제 | 전체 기능 ON/OFF 설정은 유지 |
| 서버 재시작 | 참가 예약 초기화 | 저장된 설정·봇별 닉네임·스킨·누적 전적 유지 |

```mcfunction
/gungang bot status
/gungang bot off
```

`off`는 즉시 모든 봇과 남은 투사체를 제거하고 로비 참가 예약도 해제합니다. 열린 로비에는 `봇 사용 꺼짐`이 표시되고 버튼이 비활성화됩니다. 오래된 화면이나 직접 전송한 추가 요청도 서버에서 거부합니다. 다시 사용하려면 `on` 실행 후 로비에서 새로 추가해야 합니다. 기존 경기 점수는 유지하며 경기 종료·서버 종료 때도 엔티티를 정리합니다. 오류로 자동 중지되면 `status`와 서버 로그를 확인하고 원인을 수정한 뒤 `on`을 실행합니다.

`off` 후 경기 중에 다시 `on`만 입력해도 봇은 되살아나지 않습니다. 경기를 마친 뒤 로비에서 다시 추가하세요. `/gungang stop`은 봇만이 아니라 현재 경기 전체를 종료합니다.

## 명령어와 성능 설정

모든 명령은 OP 2 권한이 필요하며 콘솔에서도 사용할 수 있습니다. `/gungang bot`만 입력하면 현재 상태를 보여줍니다.

`<주무기 ID>`, `<번호>`, `<숫자>`는 실제 값으로 바꾸며 꺾쇠는 입력하지 않습니다. `<번호>`는 봇 번호 1~4입니다. 아래 표의 `/`로 나열한 선택지는 한 번에 모두 입력하는 것이 아니라 하나를 골라 사용합니다. 세부 설정 이름은 표의 대소문자 그대로 입력하세요.

| 명령 | 기능 |
| --- | --- |
| `/gungang bot on` / `off` | 전체 기능 켜기 / 즉시 끄기 |
| `/gungang bot status` | 공통 설정, 로비 예약 수, 봇별 참가 상태·현재 행동·오류·AI 관리 처리 시간 확인 |
| `/gungang bot name <번호> <닉네임>` | 그 봇의 닉네임 저장. 경기 밖에서 변경 |
| `/gungang bot skin <번호> <텍스처>` / `default` | 그 봇의 스킨 저장. 경기 밖에서 변경. [스킨 설치](#skins) 참고 |
| `/gungang bot stats` / `stats <번호>` | 전체 또는 한 봇의 누적 전적 조회 |
| `/gungang bot reload` | 경기 밖에서 `bot-db.json`과 파일 스킨 다시 읽기 |
| `/gungang bot difficulty easy` / `normal` / `hard` / `expert` | 반응·조준 오차·회전 속도·기억 시간·시야각 일괄 설정 |
| `/gungang bot preset low` / `normal` / `high` | 탐색 주기·경로 갱신 주기·범위 일괄 설정 |
| `/gungang bot preset responsive` | 판단 5틱·경로 10틱·범위 48·반응 4틱·이동 1.1배 |
| `/gungang bot team AUTO` / `ALPHA` / `BRAVO` | 자동 배정되는 봇의 기본 팀. 경기 밖에서 변경 |
| `/gungang bot weapon auto` / `<주무기 ID>` | 모든 봇의 주무기 자동 선택 / 고정. 경기 밖에서 변경 |
| `/gungang bot secondary auto` / `none` / `<보조무기 ID>` | 모든 봇의 보조무기 자동 선택 / 사용 안 함 / 고정. 경기 밖에서 변경 |
| `/gungang bot waypoint <맵 ID> ...` | 맵 전술 지점 관리. [맵 웨이포인트](#waypoints) 참고 |
| `/gungang bot set thinkTicks <5~100>` | 적 탐색·상황 판단 간격, 정수 틱 |
| `/gungang bot set pathTicks <10~200>` | 이동 경로 재계산 간격, 정수 틱 |
| `/gungang bot set range <8~64>` | 적 탐지 반경, 정수 블록 |
| `/gungang bot set reactionTicks <2~100>` | 새 표적을 발견한 뒤 첫 사격까지 기다리는 틱(±30% 변동) |
| `/gungang bot set aimError <0.5~15>` | 조준 오차, 도 단위 |
| `/gungang bot set turnRate <2~90>` | 시야 회전 속도, 틱당 도 |
| `/gungang bot set memorySeconds <0.5~30>` | 보이지 않게 된 적을 기억하는 시간, 초 |
| `/gungang bot set fov <60~360>` | 시야각, 정수 도 |
| `/gungang bot set movementSpeed <0.5~2>` | 이동 배율. **1.0 = 같은 무기를 든 플레이어의 달리기 속도**. 즉시 반영 |

**변경 가능한 시점:** `on`, `off`, `status`, `stats`, `preset`, `difficulty`, `set`, `waypoint`는 경기 중에도 사용할 수 있습니다. `team`, `weapon`, `secondary`, `name`, `skin`, `reload`는 준비 중·경기 중에는 변경할 수 없습니다. 로비의 추가·제거는 관리자 화면에서 수행하며 `/gungang bot add`, `/gungang bot remove` 명령은 제공하지 않습니다.

팀·무기·난이도·성능 설정은 모든 봇이 공유합니다. 닉네임·스킨·누적 전적만 봇마다 따로 있습니다.

<a id="tuning"></a>

## 성능·난이도 조절 예제

정상 20 TPS에서는 20틱이 1초입니다. 설정은 두 갈래로 나뉩니다.

- **성능 프리셋**(`preset`): 판단·경로 계산 빈도와 탐지 범위. 서버 부담에 영향을 줍니다.
- **난이도**(`difficulty`): 반응·조준·시야. 봇의 실력에 영향을 줍니다.

| 성능 프리셋 | 판단 간격 | 경로 갱신 간격 | 탐지 반경 |
| --- | --- | --- | --- |
| low | 20틱 | 40틱 | 24블록 |
| normal (기본 설정) | 5틱 | 10틱 | 48블록 |
| high | 5틱 | 10틱 | 48블록 |
| responsive | 5틱 | 10틱 | 48블록 (반응 4틱·이동 1.1배도 변경) |

| 난이도 | 반응 | 조준 오차 | 회전 속도 | 적 기억 | 시야각 |
| --- | --- | --- | --- | --- | --- |
| easy | 약 450ms (9틱) | 6° | 8°/틱 | 2초 | 100° |
| normal (기본) | 약 300ms (6틱) | 3.5° | 14°/틱 | 3초 | 110° |
| hard | 약 130~230ms (4틱) | 2° | 22°/틱 | 4초 | 120° |
| expert | 약 100ms (2틱) | 1° | 35°/틱 | 6초 | 130° |

난이도 값은 조정을 시작하기 위한 기준이며 실측한 명중률이 아닙니다. 실제 명중률은 무기와 맵에 따라 달라집니다. `set`으로 실력 값을 하나라도 직접 바꾸면 난이도 표시는 `custom`이 됩니다. `high`는 normal보다 탐지 범위가 넓은 설정이며, 서버 상태에 따른 자동 프리셋 전환은 없습니다.

### 서버 부담을 줄여서 시작

```mcfunction
/gungang bot preset low
/gungang bot status
```

적 탐색은 약 1초마다, 경로 갱신은 약 2초마다 수행하고 탐지 범위는 24블록으로 설정합니다(20 TPS 기준). 이동·투사체 등 엔티티 처리까지 이 간격으로 늦추는 것은 아닙니다. 봇을 여러 명 넣으면 봇 수만큼 계산이 늘어나므로, 4명을 넣을 때는 `status`의 처리 시간을 먼저 확인하세요.

더 낮은 빈도로 시험하려면 다음과 같이 조절할 수 있습니다. 대신 적 발견과 경로 변경이 느려집니다.

```mcfunction
/gungang bot set thinkTicks 40
/gungang bot set pathTicks 80
/gungang bot set range 16
```

### 조작에 익숙하지 않은 사람과 연습

```mcfunction
/gungang bot difficulty easy
```

반응이 느리고 조준 오차가 크며, 시야가 좁아 옆이나 뒤의 적을 늦게 알아챕니다. 실제 첫 사격 시점에는 탐색 간격과 총기 꺼내기·재장전·발사 간격도 영향을 줍니다. `reactionTicks`는 매 발 사이의 간격을 지정하는 값이 아닙니다.

### 반응과 조준을 더 날카롭게 설정

```mcfunction
/gungang bot preset responsive
/gungang bot difficulty expert
```

이 값들은 행동 설정이며 학습을 시작하거나 AI 모델을 변경하지 않습니다. `aimError`를 줄여도 총기의 자체 탄퍼짐이나 탄도까지 없어지지는 않습니다.

### 기본 성능·난이도 값으로 복구

```mcfunction
/gungang bot preset normal
/gungang bot difficulty normal
/gungang bot set movementSpeed 1.0
```

위 명령은 팀·무기·전체 ON/OFF를 초기화하지 않습니다. 모든 수치는 허용 범위를 벗어나면 거부하며, `aimError`, `movementSpeed`, `turnRate`, `memorySeconds`를 제외한 숫자는 정수만 받습니다.

성능과 난이도 설정은 경기 중에도 변경할 수 있습니다. 명령으로 바꾼 값은 `config/gungang/server/bot.json`에 저장되며 재시작 후에도 유지됩니다. 파일을 직접 편집했다면 서버를 재시작합니다. `/gungang reload`는 봇 설정을 다시 읽지 않습니다.

`status`의 시간은 모든 봇의 관리 코드 호출 시간 평균·최댓값입니다. 경로 계산은 포함하지만 Minecraft 엔티티 틱, TaCZ 투사체 틱, 네트워크 전송 등 전체 비용을 모두 포함하지 않습니다. 서버 전체 부하는 실제 경기의 틱 처리 시간과 함께 확인해야 합니다. `off`해도 이미 로드한 청크나 JVM 메모리가 즉시 회수되는 것은 아닙니다.

## 무기 선택

봇은 `config/gungang/server/weapons/*.json`에 등록된 주무기를 사용합니다. 사람의 현재 손에 든 무기를 복사하는 기능은 아닙니다. 무기 설정은 모든 봇에 공통이며, 자동 선택이면 봇마다 각자 판단합니다.

1. 로비 또는 경기 밖에서 `/gungang bot weapon `까지 입력하고 TAB으로 등록된 ID를 확인합니다.
2. 지원되는 주무기 ID를 골라 명령을 실행합니다.
3. `/gungang bot status`에서 설정값을 확인한 뒤 로비에 봇을 추가합니다.

자동 선택은 다음과 같습니다.

```mcfunction
/gungang bot weapon auto
```

등록된 주무기 중 **TaCZ 총기 또는 바닐라 활**을 후보로 삼습니다. 첫 출전과 사망 후 리스폰 때 아래 판단 규칙으로 선택합니다. 지원되는 무기가 하나도 없거나 지정한 무기가 없으면 추가·무기 변경 시 오류가 표시됩니다.

예를 들어 무기 JSON의 `id`가 `training_rifle`인 총기를 실제로 등록했다면 `/gungang bot weapon training_rifle`을 사용합니다. 파일명이 `01_rifle.json`이어도 `01_rifle`을 쓰는 것이 아니며, `tacz:ak47` 같은 총기 팩 ID나 `tacz:modern_kinetic_gun` 같은 아이템 ID를 대신 입력해서도 안 됩니다.

TaCZ가 없는 환경에서는 등록된 바닐라 활을 선택하세요. 기본 예제 `bow`가 남아 있다면 `/gungang bot weapon bow`로 시험할 수 있습니다.

### 보조무기

보조무기는 `server/sub_weapons/*.json`에서 선택합니다. `/gungang bot secondary auto`는 지원 항목을 비교해 선택하며, `/gungang bot secondary 81`처럼 등록된 ID를 지정할 수도 있습니다. **명령어 전용 장비와 폭탄·해체기를 제외한 모든 보조무기**를 사용합니다.

| 종류 | 봇의 사용 방식 |
| --- | --- |
| TaCZ 총기, 활, 근접무기 | 손에 들고 사용. 근접무기는 바닐라 검·도끼와 공격력 속성이 있는 모드 근접무기(예: lrtactical 카람빗) |
| 몰로토프 | 적이 7~19블록 거리에 보일 때 투척 |
| 지뢰, 베어트랩 | 적 없이 한동안 이동하면 경로에 설치. 6블록 안에 이미 설치한 것이 있으면 생략 |
| 방벽 | 교전 중 체력이 줄고 공격받을 때 적과 자기 사이에 설치 |
| 궤도폭격 | 보이는 먼 적에게 사용. 자신이나 아군이 폭발 범위 안이면 사용하지 않음 |
| 회복약, 전투자극제 | 회복약은 체력이 줄었을 때, 전투자극제는 교전 중 체력에 여유가 있을 때 |
| 적외선 스캐너 | 적이 안 보인 지 몇 초 지나면 사용. 아군에게도 적 위치가 표시됨 |
| 방패 | 체력이 낮고 공격받을 때 들어 올리고 뒤로 물러남. 든 동안 사격하지 않음 |
| 생명 유지 장치 | 치명상 시 자동 발동 |
| 제트팩 | 적이 안 보이고 목적지가 멀며 앞이 트였을 때 그 방향으로 비행 |
| lrtactical 수류탄·연막탄 등 기타 아이템 | 봇과 같은 UUID의 가상 플레이어로 사용. 투척물 주인과 킬이 봇으로 기록됨 |

장비 사용 시점은 상황 점수(0~1)로 판단하며, 약간의 무작위 값을 더해 0.5를 넘으면 사용합니다. 쿨타임은 플레이어와 같은 설정을 따르고 봇이 죽었다 살아나도 유지됩니다. 장비형 보조무기는 봇의 왼손에 보입니다. 봇이 사용할 수 없는 아이템은 그 생애 동안만 사용을 멈추고 로그를 남깁니다. lrtactical 계열은 해당 모드가 설치된 환경에서 따로 확인이 필요합니다.

주무기 탄창이 비면 보조 총기/활로 전환합니다. 보조무기는 자체 탄약·재장전을 사용하며, 교전이 끊기거나 약 10초가 지나면 주무기로 돌아옵니다. 무기를 바꿔도 탄창·예비탄을 초기화하지 않습니다. 근접 보조무기는 3블록 이내에서 꺼내고 2.8블록 이내에서 공격하며, 적이 멀어지면 주무기로 돌아옵니다. 반복 전환을 막기 위해 전환 사이에는 최소 3초 간격을 둡니다. 총기의 실제 꺼내기·연사·재장전 시간은 그대로 적용합니다.

### 사망 후 자율 장비 선택

경기 밖에서 다음을 실행하면 주무기와 보조무기 모두 봇이 선택합니다.

```mcfunction
/gungang bot weapon auto
/gungang bot secondary auto
```

- 각 슬롯을 독립적으로 판단합니다. ID를 직접 지정한 슬롯은 사망해도 그대로 유지하며, `secondary none`은 계속 보조무기를 사용하지 않습니다.
- 주무기는 JSON의 `maxHealth`·`movementSpeed` 외에 무기별 적정 사거리와 TaCZ의 기본 피해량·발사속도·탄창·재장전 시간을 비교합니다. 메타데이터를 읽지 못하는 총기 팩은 카테고리와 보수적인 기본값을 사용합니다.
- 직전 생존 중 적에게 준 피해가 50 이상이거나, 30초 이상 생존하며 피해를 주었다면 성과가 있다고 보고 기존 자동 장비를 유지합니다.
- 교전 성과가 낮으면 다른 후보에 우선순위를 줍니다. 10초 안에 사망했다면 주무기의 체력 가중치를 높입니다. 보조무기는 봇이 실제로 본 적과의 최근 거리로 근접·원거리 적합성을 비교합니다. 원거리 교전에 적합한 대안이 없으면 무조건 근접무기로 바꾸지 않습니다.
- 보조장비는 짧은 생존 시 회복·방어, 먼 교전 시 스캐너·폭격 등 역할 적합성도 비교합니다. 장비별 최근 네 생애의 교전 성과를 경기 안에서 기억해 반복해서 실패한 후보를 낮게 평가합니다. 보조장비 기록은 해당 장비를 장착했던 생애의 전체 성과이며 그 장비만의 기여도를 분리한 값은 아닙니다.
- 적을 관측하거나 피해를 준 적 없이 환경 요인으로 죽었다면 장비를 유지합니다. 후보가 하나뿐이면 같은 무기로 부활합니다.
- 선택한 장비는 리스폰할 때 지급하며 해당 주무기의 최대 체력과 현재 무기의 이동 속도를 적용합니다. 경기 도중 후보 JSON을 매 틱 읽지 않고 경기 시작 시 읽은 지원 목록을 사용합니다.

`/gungang bot status`에 봇별 출전 장비 ID를 표시하며, 판단 이유는 서버 로그에 남깁니다. 이 기능은 규칙 기반 판단입니다. 총기 설명문의 모든 수치를 해석하거나 장기 학습하는 기능은 아니며, 판단에 쓰는 교전 기록은 경기 종료 때 초기화됩니다. 누적 전적 DB는 그대로 유지됩니다.

<a id="configuration"></a>

## 설정 파일과 저장 범위

파일 위치는 **실행 중인 서버 폴더 기준** `config/gungang/server/bot.json`입니다. 개발 프로젝트의 예제 파일을 편집해도 실행 서버의 파일에 자동 반영되지는 않습니다.

```json
{
  "enabled": false,
  "team": "AUTO",
  "weapon": "",
  "thinkTicks": 5,
  "pathTicks": 10,
  "range": 48,
  "reactionTicks": 6,
  "aimError": 3.5,
  "secondary": "",
  "movementSpeed": 1.0,
  "turnRate": 14.0,
  "memorySeconds": 3.0,
  "fov": 110,
  "difficulty": "normal"
}
```

| 키 | 기본값 | 의미 |
| --- | --- | --- |
| `enabled` | `false` | 전체 사용 허용. `true`여도 로비에서 별도 추가 필요 |
| `team` | `"AUTO"` | 자동 배정되는 봇의 팀. `"ALPHA"`, `"BRAVO"`로 고정 가능 |
| `weapon` | `""` | 빈 문자열이면 자동 선택. 지정 시 주무기 JSON의 ID |
| `thinkTicks` | `5` | 판단 주기. 5~100 |
| `pathTicks` | `10` | 경로 재계산 주기. 10~200 |
| `range` | `48` | 주변 탐색 반경. 8~64블록. 적 시각 인지는 최소 48블록을 사용 |
| `reactionTicks` | `6` | 새 표적에 대한 반응 지연. 2~100 |
| `aimError` | `3.5` | 조준 오차. 0.5~15도 |
| `secondary` | `""` | 보조무기 자동 선택. `"none"`으로 끄거나 보조무기 ID 지정 |
| `movementSpeed` | `1.0` | 이동 배율. 1.0 = 같은 무기를 든 플레이어의 달리기 속도. 0.5~2 |
| `turnRate` | `14.0` | 시야 회전 속도. 2~90도/틱 |
| `memorySeconds` | `3.0` | 보이지 않게 된 적 기억 시간. 0.5~30초 |
| `fov` | `110` | 시야각. 60~360도 |
| `difficulty` | `"normal"` | 마지막으로 적용한 난이도 이름. 직접 값을 바꾸면 `"custom"` |

> **`movementSpeed` 의미가 바뀌었습니다.** 예전에는 내부 속도 값에 곱하는 배율이라 1.25여도 실제로는 걷는 속도였습니다. 지금은 1.0이 플레이어의 달리기 속도입니다. 예전 파일의 1.25·1.35가 그대로 남아 있으면 봇이 플레이어보다 25~35% 빠르므로 `/gungang bot set movementSpeed 1.0`으로 맞추세요.

새 필드가 없는 기존 파일은 회전 14°/틱, 기억 3초, 시야 110°로 읽으며 다음 설정 저장 시 새 필드가 추가됩니다. 이전의 느린 설정을 쓰고 있다면 `/gungang bot difficulty normal`과 `/gungang bot preset normal`을 실행하세요.

명령어로 변경하면 저장과 적용을 함께 수행합니다. 직접 수정할 때는 서버를 종료하고 전체 형식을 유지해 UTF-8 JSON으로 저장한 뒤 다시 시작하세요. **명령에서는 `weapon auto`, 파일에서는 `"weapon": ""`**라는 차이가 있습니다. `"weapon": "auto"`는 자동 선택이 아니라 `auto`라는 무기 ID로 해석됩니다.

서버 재시작 후에는 저장한 설정과 봇별 프로필·누적 전적이 복원됩니다. 로비에 봇을 추가했다는 예약, 현재 위치·체력·표적·경기 상태를 복구하지는 않습니다. 봇 인원은 로비에서 정하며 최대 4명입니다.

`/gungang reload`는 이 파일을 다시 읽지 않습니다. 잘못된 JSON이나 허용 범위를 벗어난 값이 있으면 서버 시작 시 봇 기능을 비활성화하고 로그에 오류를 남깁니다. 파일을 바로잡은 뒤 재시작하거나 정상 값을 관리자 명령으로 다시 저장하세요.

<a id="waypoints"></a>

## 맵 웨이포인트

웨이포인트는 맵 제작자가 지정하는 전술 지점입니다. 없어도 봇은 맵을 스스로 살펴 이동하지만, 지정하면 그 지점을 우선 사용해 더 전술적으로 움직입니다. 맵마다 `config/gungang/server/bot_waypoints/<맵 ID>.json`에 저장됩니다.

| 종류 | 봇의 사용 |
| --- | --- |
| `route` | 순찰 경로 |
| `cover` | 엄폐 위치 후보. 근처 16블록 안의 지점을 직접 찾은 후보와 함께 비교 |
| `sniper` | 순찰 중 들르는 저격·감시 지점 |
| `objective` | 순찰 중 들르는 주요 거점 |

```mcfunction
/gungang bot waypoint <맵 ID> add cover
/gungang bot waypoint <맵 ID> add sniper bravo
/gungang bot waypoint <맵 ID> list
/gungang bot waypoint <맵 ID> show
/gungang bot waypoint <맵 ID> remove
/gungang bot waypoint <맵 ID> clear
```

- `add <종류> [any|alpha|bravo]`: 명령을 실행한 위치(발밑 블록 중앙)에 지점을 추가합니다. 팀을 지정하면 그 팀 봇만 사용합니다. 기본은 `any`입니다.
- `remove`: 3블록 안에서 가장 가까운 지점을 지웁니다.
- `show`: 실행한 관리자에게만 파티클로 지점을 보여 줍니다(엄폐 초록, 저격 불꽃, 거점 빛, 경로 구름).
- 맵당 최대 512개입니다. 파일이 깨져 있으면 로그에 경고를 남기고 웨이포인트 없이 동작합니다.
- 순찰 목표는 다섯 번 중 한 번꼴로 웨이포인트 대신 직접 고르므로, 봇이 항상 같은 길만 다니지는 않습니다.

<a id="troubleshooting"></a>

## 상태 조회와 문제 해결

먼저 `/gungang bot status` 또는 `/gungang bot`을 실행합니다. 첫 줄에 ON/OFF, 로비 예약 수(`로비 n/4명`), 경기 여부가 나오고, 공통 설정 다음 줄부터 봇마다 한 줄씩 표시됩니다.

| 상태 문구 | 확인할 내용 |
| --- | --- |
| `OFF` | 전체 기능이 꺼짐. 사용하려면 관리자가 `on` 실행 |
| `로비 0/4명` | 기능은 허용됨. 로비에서 별도 추가 필요 |
| `Rookie: 로비 대기 · BRAVO팀` | 참가 예약 완료. 경기 시작을 기다리는 상태 |
| `Rookie: BRAVO팀 · 행동=…` | 해당 팀으로 엔티티가 생성된 상태. 현재 행동, 주요 행동 점수(임무 점수 포함), 현재 임무(`임무=A 지점 설치` 등, 없으면 `없음`), 인지한 적 수, 기억하는 위험 지점 수, 장비를 표시. 개인전에서는 `개인전 n점 n위`와 리스폰 무적 여부도 표시 |
| `리스폰 대기` | 사망 후 부활 대기 |
| `오류: ...` | 봇 실행이나 설정 읽기 실패. 서버 `logs/latest.log`의 관련 오류 확인 |

봇 줄의 `행동=`에는 지금 하고 있는 일(교전, 엄폐 후 재정비, 후퇴, 아군 합류, 아군 지원, 회복, 추적·확인, 임무 수행, 순찰, 위험 지역 이탈 등)과 경과 시간이 나옵니다. `/gungang bot debug info`의 이동 상태에는 맵 경로망 단계(`맵 경로 이동 (남은 n단계)`, `점프대 비행`, `셔터 스위치로 이동`, `셔터 열림 대기`, `셔터를 열 수 없음: 우회` 등)가 표시됩니다. 봇이 이상하게 움직이면 이 줄을 먼저 확인하세요.

| 증상 | 확인·해결 순서 |
| --- | --- |
| 봇 추가 버튼이 보이지 않음 | 서버·클라이언트가 같은 버전인지 확인하고 `플레이어 / 팀` 탭으로 이동 |
| `봇 사용 꺼짐`으로 비활성화 | 관리자 또는 콘솔에서 `/gungang bot on` 실행 |
| 켰는데도 버튼을 못 누름 | OP 2 권한, 로비 단계인지 확인. 준비·경기 중에는 추가 불가. `4/4`이면 최대 인원 |
| `on`을 했는데 봇이 없음 | `on`은 허용만 함. 로비에서 `봇 추가` 후 경기를 시작 |
| 로비 명단에는 있는데 월드에는 없음 | 로비에서는 참가 예약만 표시. 경기 준비가 시작되면 실제 봇 생성 |
| 사람이 혼자라 시작을 못 함 | 본인을 ALPHA 또는 BRAVO에 배정하고 준비. 미배정 참가자가 남아 있는지 확인 |
| 이름을 끌어도 팀이 안 바뀜 | 로비 단계인지, 다른 사람이나 봇을 옮기려면 OP 2인지 확인. 봇은 관전자 칸으로 옮길 수 없음 |
| 봇이 적을 공격하지 않음 | 같은 팀·관전자·크리에이티브 모드가 아닌지, 부활 대기나 준비 시간이 아닌지 확인. 탐지 거리, 시야각(`fov`), 벽·스폰 게이트도 확인 |
| 봇이 스폰 방에 머묾 | 방의 출입구가 그 팀의 스폰 게이트인지 확인. 게이트 바깥 2블록에 서 있을 바닥이 있어야 출구로 인식 |
| 봇이 멈추거나 목적지에 못 감 | 스폰 위치와 바닥, 경로 연결, 문·복층·점프 구간 확인. 3초간 진척이 없으면 다른 목적지로 바꿈. 긴 맵은 서버 로그의 `Bot map grid ready` 줄로 맵 경로망 생성을 확인([맵 경로망](#navigation)). 웨이포인트로 경로를 지정하면 도움이 됨 |
| 셔터 앞에서 돌아감 | 셔터 근처(가로 8·세로 4블록 이내)에 레버·버튼이 있는지, 봇 쪽에서 걸어가 닿을 수 있는지 확인. 스위치가 다른 셔터에 연결돼 있으면 한 번 시도 후 되돌리고 우회 |
| 점프대를 쓰지 않음 | 착지 지점이 가로 7블록 이내·발판 높이 이하인지, 비행 궤적(수직 상승 후 수평 이동)에 천장·벽이 없는지 확인 |
| 폭탄을 설치하지 않음 | 공격팀 플레이어가 A/B 설치 구역 위에 팀 포인트(Q)를 찍었는지 확인. 공격팀 사람이 모두 죽었거나 없으면 봇이 직접 지점을 고름 |
| 움직임이 느리거나 빠름 | `status`에서 이동 배율 확인. 1.0이 플레이어 달리기 속도 |
| 보조무기를 쓰지 않음 | `secondary auto` 또는 지원 ID 지정. 장비는 점수가 기준을 넘는 상황에서만 사용하며 `status`에 점수와 쿨타임이 표시됨 |
| 힐팩을 찾아가지 않음 | 체력이 낮은지, 팩이 쿨타임 중인지, 탐지 반경·높이 범위 및 걸어갈 수 있는 경로인지 확인 |
| 무기 오류가 나거나 총을 못 씀 | 주무기 JSON의 ID, TaCZ 설치와 총기 팩, 지원 무기인지 확인. `weapon auto` 또는 등록된 활로 비교 |
| 성능 저하가 의심됨 | 같은 맵·비슷한 교전 상황에서 봇 수를 줄이거나 ON/OFF 비교 후 `preset low` 적용. 필요하면 `off`로 즉시 중단 |
| `off` 후 다시 `on`했지만 참가 안 함 | OFF가 예약도 지움. 경기 종료 후 로비에서 다시 추가 |
| 파일 수정이 반영되지 않음 | 실행 서버의 `bot.json`인지 확인. 직접 수정은 재시작 필요, `/gungang reload` 대상 아님 |
| 다시 켠 뒤 점수판에 예전 봇 기록이 남음 | 현재 경기의 기록은 삭제하지 않는 정상 동작. 새 경기에서 초기화 |

오류를 조사할 때는 `status` 내용, 사용한 무기 ID, 맵 ID, 오류가 발생한 시각과 `logs/latest.log`의 해당 구간을 함께 기록하면 원인을 좁히기 쉽습니다. 운영 서버의 다른 애드온이나 맵 구조에 따른 문제는 기본 환경과 비교해서 확인하세요.

<a id="behavior"></a>

## 전투와 제한

봇은 매 틱 **인지 → 판단 → 실행 → 조준·사격** 순서로 움직입니다.

### 인지: 실제로 알 수 있는 정보만 사용

- **시야:** 시야각(`fov`) 안에 있고 벽에 막히지 않은 적만 봅니다. 4블록 안은 시야각과 관계없이 알아챕니다.
- **먼 적 대응:** 기존 설정의 `range`가 작아도 적 시각 인지는 최소 48블록까지 수행합니다. 48보다 큰 설정은 그대로 반영합니다. 보인다고 즉시 사격하지 않고 무기 역할별 교전 사거리 밖이면 접근합니다. 24블록보다 먼 적을 발견했을 때 체력 45% 미만·탄창 15% 미만·주변 아군을 고려한 수적 열세 2명 이상이면 피격 전에도 후퇴를 우선합니다.
- **팀 포인트:** 같은 팀원이 Q로 지정한 최신 포인트를 인식합니다. 즉시 교전·피격·위험 회피·회복할 일이 없을 때 확인하러 이동하며, 도착하거나 접근에 실패한 포인트를 계속 반복 추적하지 않습니다. 새 포인트가 오면 다시 판단합니다. [팀 포인트 사용법](TEAM-POINTS.md)을 참고하세요.
- **청각:** 48블록 안의 적 총소리(TaCZ 사격·활)와 14블록 안에서 웅크리지 않고 움직이는 적의 발소리를 듣습니다. 소리로 안 위치는 멀수록 오차가 큽니다.
- **피격과 무전:** 적에게 맞으면 탐지 반경 밖에서도 공격한 쪽을 기억하고 엄폐·후퇴 판단에 반영합니다. 이 기억만으로 탐지 반경 밖의 적을 사격 대상으로 삼지는 않습니다. 아군(플레이어·봇)이 맞으면 공격자의 대략적인 위치를 알게 됩니다.
- **지원 위치:** 아군 지원도 접촉 기억과 같은 제보 위치(X/Z 각 ±3블록 오차)를 사용합니다. 봇이 직접 본 최신 위치가 있으면 이를 우선하며, 새 제보 없이 벽 뒤 적의 이동을 따라 갱신하지 않습니다.
- **스캔:** 같은 팀 누군가 적외선 스캐너를 쓰면 스캔이 켜진 동안 64블록 안 적 위치를 압니다.
- **기억:** 안 보이게 된 적은 `memorySeconds` 동안 기억하며, 마지막으로 본 이동 방향으로 약 1초 앞을 예측해 추적합니다. 벽 너머의 현재 위치를 추적하지는 않습니다.
- **위험 지형:** 10블록 안에서 본 적 지뢰·베어트랩은 사라질 때까지 기억하고 길을 돌아갑니다. 몰로토프 불장판과 궤도폭격 경고 범위는 아군 것도 피하며, 범위 안에 있으면 빠져나가는 것을 가장 먼저 합니다.

### 판단: 행동 점수

교전, 돌격, 엄폐 후 재정비, 후퇴, 아군 합류, 아군 지원, 회복, 추적·확인, 순찰, 위험 지역 이탈에 매번 0~100점을 매겨 가장 높은 행동을 고릅니다. 점수는 체력, 탄약, 재장전 여부, 보이는 적 수와 아군 수(수적 열세), 거리, 피격 여부, 아군 생존 여부로 계산합니다. 점수가 비슷할 때 행동이 흔들리지 않도록 지금 행동에 가산점을 주고, 급한 상황(재장전, 큰 점수 차)에서는 바로 바꿉니다. 실패한 행동은 4초 동안 점수를 낮춥니다. 점수는 조정을 위한 기준값이며 실측값이 아닙니다.

### 실행과 이동

- 선택한 행동은 단계별로 실행합니다. 예를 들어 엄폐는 후보 검색 → 이동 → 재장전·관측 → 재교전 순서이며, 이동 중 크게 맞거나 도달할 수 없으면 중단하고 다시 판단합니다.
- 횡이동은 양쪽 방향의 몸 충돌·바닥 지지·데스존을 확인합니다. 양쪽이 막히면 멈춘 뒤 가까운 안전한 교전 위치를 찾습니다.
- 횡이동의 첫 방향이 안전하면 검사 결과를 재사용하며, 방향을 바꿀 때만 반대 방향을 검사합니다. 근접 무기 추격도 공통 경로 계산 예산과 실패 목적지 재시도 제한을 적용합니다. 적에게 접근하면 순찰 목적지를 새로 고르지 않고 멈춰 공격합니다.
- 스폰 출구는 로딩된 청크에서 먼저 찾습니다. 탐색 범위의 다른 청크가 아직 로딩되지 않았어도 발견한 출구를 사용하며, 불완전한 검색 결과를 전체 출구 목록으로 캐시하지 않습니다. 발견한 출구로 나가는 이동은 일반 `pathTicks` 대기와 분리하고, 출구를 지나 자기 스폰에서 이탈 거리(두 스폰 간 거리의 40%, 최소 8·최대 24블록) 이상 떨어지고 스폰 구역을 벗어난 후 일반 행동으로 전환합니다. 눈앞의 적·피격·위험 지역·낮은 체력 대응은 우선합니다.
- 준비 시간에는 게이트가 닫혀 있으므로 출구 경로 탐색을 경기 시작 후로 미룹니다. 준비 중에 출구가 막힌 것으로 판단하고 그 결과를 경기 중까지 유지하지 않습니다.
- 스폰 직후 지면 판정이 아직 없으면 출구 탐색을 잠시 미뤄 재시도합니다. 스폰 구역이 실제 스폰 좌표를 포함하지 않으면 실제 좌표 주변에서 출구를 찾습니다. 출구 도착 후에는 순찰 경로 갱신을 즉시 허용합니다.
- 엄폐 탐색에서 계산한 경로를 엄폐 이동에 재사용합니다. 이동 중인 경로는 일반 갱신 주기만으로 다시 계산하지 않으며, 경로 종료·엄폐 무효·시간 초과 시 다시 판단합니다.
- 회복 행동은 사용 가능한 주변 힐팩 후보가 있을 때 선택합니다. 후보 목록은 40틱 간격 또는 8블록 이상 이동 시 갱신하고, 제거·쿨타임·경로 실패 대기 상태를 걸러 냅니다. 후보 확인 자체는 경로 계산 예산을 사용하지 않으며 실제 접근 가능 여부는 이동 시 확인합니다.
- 순찰·추적에서 경로 탐색에 실패하거나 이동이 막혀 포기한 목적지는 200틱(20 TPS에서 10초) 동안 재선택하지 않습니다. 실패 목적지의 3블록 이내에도 적용하며, 실패 당시 위치에서 8블록 이상 이동하면 다른 접근으로 보고 다시 시도합니다. 경로 계산 예산 부족은 실패로 기록하지 않고, 리스폰 시 실패 기록을 초기화합니다.
- 탄창이 거의 비면 엄폐를 우선하며, 엄폐 도착 후 안전하고 탄약이 절반 미만이면 선제 재장전합니다. TaCZ 실제 재장전 상태를 사용하며 구형 API에서는 시간 추정으로 대체합니다.
- 엄폐 위치에서 재장전을 마치면 가까운 사격 각도를 찾고, 잠깐 노출해 사격한 뒤 같은 엄폐로 복귀합니다. 피격·탄약 부족 시 먼저 복귀하며, 안전한 왕복 경로가 없으면 노출하지 않습니다.
- 엄폐 지점은 알고 있는 모든 적의 시선이 가려지는 곳 중에서 이동 거리, 적에게 다가가지 않는지, 아군과 가까운지를 따져 고릅니다.
- 교전 거리는 TaCZ 총기 팩의 분류를 우선 사용합니다. 기본 유지 거리는 산탄총 3–8, 기관단총·권총 5–12, 소총 10–20, 저격총 20–34블록입니다. 실제 탐지는 `range` 설정에 제한되며, 분류를 읽지 못하면 장비 카테고리 또는 소총 기준을 사용합니다.
- 순찰은 웨이포인트 또는 두 스폰 사이에서 고른 지점을 도착하거나 막힐 때까지 유지합니다. 2초간 진척이 없으면 점프하고 3초면 다른 지점으로 바꿉니다. 부활하면 자기 팀 스폰 게이트를 찾아 먼저 스폰 방을 나갑니다.
- 같은 X/Z의 다른 층에 있는 목적지는 도착으로 처리하지 않습니다. 지면 후보는 요청한 높이에 가까운 층부터 확인하며, 저격 무기는 `SNIPER`, 근거리 무기는 `OBJECTIVE`, 일반 무기는 `ROUTE` 지점을 우선 평가합니다. 계단·문 등의 연결은 Minecraft 길찾기에 의존합니다.
- 발견한 위험 장비는 일반 경로뿐 아니라 좌우 이동·엄폐 왕복의 몸체 폭까지 검사합니다. 화염·폭격 안에서는 재장전·엄폐 유지·방패 행동보다 이탈이 우선이며, 이탈 실패에 일반 행동의 4초 억제를 적용하지 않습니다.
- 위험물의 96블록 광역 탐색은 최소 20틱 간격으로 수행합니다. 그 사이에는 가까운 범위(24블록과 설정된 폭격 반경+3 중 큰 값)를 기존 판단 주기마다 탐색하며, 사라진 위험물도 매 판단 시 정리합니다. 먼 폭격 표식 발견은 다음 광역 탐색까지 늦어질 수 있습니다.
- 플레이어와 멀리 떨어져 있어도 준비 시간부터 봇 주변 청크를 계속 활성 상태로 유지합니다. 20블록보다 먼 목적지는 [맵 경로망](#navigation)으로 전체 경로를 계산해 약 8칸 간격의 경유점을 따라 이동합니다. 경로망이 아직 없거나 맵 밖이면 기존처럼 최대 24블록씩 나누어 이동합니다. 스폰 주변 청크가 아직 준비되지 않았으면 출구 검색을 재시도합니다.
- 순찰·추적 이동 중 일반 경로가 끊기면 가까운 착지대를 찾아 파쿠르 점프를 시도합니다. 빈칸 1~3블록, 같거나 최대 1블록 높은 바닥을 대상으로 몸 전체의 점프 궤적·머리 공간·착지 바닥·맵 데스존·알고 있는 위험 장비를 확인합니다. 일반 점프 속도로 부족하면 대시 점프로 전환하며, 3블록 틈 너머의 한 칸 높은 발판도 궤적이 안전하면 오릅니다. 착지 후에는 기존 달리기 상태로 돌아갑니다. 허용 거리를 넘는 점프나 낮은 천장, 착지대 없는 낭떠러지는 건너뛰지 않습니다. 점프 중에는 이동을 우선하고 착지 후 전투 판단을 재개합니다. 복잡한 연속 파쿠르 전체 경로를 미리 푸는 기능은 아닙니다.

### 조준

새 표적을 보면 반응 지연(±30% 변동) 뒤에 사격합니다. 시야는 `turnRate`만큼만 돌고, 처음 겨눌 때 생긴 오차가 짧은 시간에 걸쳐 줄어들며 작은 떨림은 남습니다. 총알은 현재 조준 방향으로 나가므로 빗나갈 수 있습니다. 활처럼 투사체가 날아가는 무기는 적의 이동 속도를 보고 앞쪽을 겨눕니다.

TaCZ 총기 팩의 탄속·중력·감속으로 비행 시간을 추정하며, 지원 API에서는 부착물/사격 모드의 탄속 캐시와 전역 탄속 배율도 반영합니다. 활은 화살의 속도·중력·감속을 사용합니다. 아군 사선 검사는 실제 조준 방향의 예상 곡선과 여유 폭을 따라 수행합니다. 총기 팩의 사용자 정의 발사 스크립트, 모든 부착물의 피해 보정, 무작위 산포 전체를 정확히 재현하는 탄도 시뮬레이터는 아닙니다.

### 팀플레이와 봇끼리

- 봇은 다른 팀의 플레이어와 봇을 모두 적으로, 같은 팀 플레이어와 봇을 아군으로 봅니다. 아군에게 피해를 주지 않고, 아군이 사선에 있으면 쏘지 않습니다. 개인전에서는 자기 외의 모든 참가자가 적입니다.
- 아군이 멀면 합류하되 바로 뒤를 따라다니지 않고 옆 4블록에 자리를 잡습니다. 순찰 목표는 아군 6블록 안을 피해 서로 다른 길을 맡습니다.
- 아군이 교전 중이면 60~80° 다른 각도로 돌아가 지원합니다. 아군이 모두 죽으면 엄폐·후퇴 비중이 커지고 돌격 비중이 줄어듭니다.

### 기타

- 기본 외형은 Steve, 이름은 `Rookie`, `Rookie 2` 같은 봇별 이름이며 닉네임과 스킨을 변경할 수 있습니다. 이름에 접두사는 붙지 않습니다. 실제 계정이나 접속 슬롯을 사용하지 않습니다.
- TaCZ 총기는 실제 사격·탄약·재장전 API와 투사체를 사용합니다. 봇은 부활마다 예비탄 10,000발을 받습니다. 총기 모드가 없는 환경에서는 등록된 활로 테스트할 수 있습니다.
- 주무기의 체력 설정을 적용하고, 이동 속도는 현재 무기의 이동 속도 설정에 봇 이동 배율을 곱합니다.
- 체력이 낮으면 로드된 주변 청크에서 사용 가능한 힐팩을 찾습니다. 탐색 반경은 `range`와 32블록 중 작은 값, 높이 차이는 8블록 이내입니다. 가까운 후보 최대 4개에 경로를 확인하며 검색 간격은 최소 40틱입니다. 접근 가능한 팩으로 이동해 밟으면 사람과 동일한 회복량·공용 재사용 대기시간을 적용합니다. 준비 중·OFF 상태에서는 봇이 팩을 소비하지 않습니다. 10초간 도착하지 못한 팩은 잠시 제외합니다. 전투 밖 자연 회복도 플레이어와 같은 규칙입니다.
- 가스통·불발탄 폭발, 산성 독, 웅덩이 발소리, 플레이어 제트팩 충돌·불꽃, 적외선 스캐너 표시는 봇에게도 플레이어와 똑같이 적용됩니다.
- 봇 킬·데스·피해량은 경기 점수와 결과에 포함하며, 누적 전적은 별도 `bot-db.json`에 봇별로 저장합니다. 봇도 플레이어와 같은 경험치 규칙(승패 기본 보상과 팀 내 기여도 비율)으로 경험치를 쌓고, 같은 경험치 표로 레벨을 계산합니다. Tab 경기 통계에 플레이어처럼 레벨 엠블럼이 표시됩니다. 봇 경험치는 `bot-db.json`에만 저장되고, 사람의 경험치 보상 계산에는 봇 기록을 포함하지 않습니다. 사람의 봇 상대 전적은 기존 경기 규칙대로 기록합니다.
- 봇 사망 시 기존 `respawnSeconds` 뒤 팀의 현재 스폰에서 다시 참가합니다(개인전은 개인전 스폰, 이동점령 공격팀은 현재 거점의 공격 스폰, 호위는 체크포인트별 스폰). 폭탄전은 리스폰 없이 다음 라운드에 참가합니다. 준비 시간에는 공격과 피해를 막고, 맵 데스존도 적용합니다.
- 사람을 자동 관찰하거나 학습하지 않습니다.

## 게임 모드별 규칙과 임무

봇은 모드마다 **임무**를 인식합니다. 임무는 HUD에서 플레이어가 보는 정보(거점 소유·진행도·경합, 수레 상태, 설치된 폭탄 위치 등)로만 판단하며 숨은 적의 위치는 사용하지 않습니다. 임무는 행동 점수의 **임무 수행** 항목으로 다른 행동과 비교합니다.

- 임무 구역 밖에서 적이 보이면 교전이 먼저입니다. 임무 구역 안에서는 구역을 떠나지 않고 그 자리에서 싸웁니다.
- 임무 수행 중 옆걸음은 구역 경계를 넘지 않도록 제한합니다. 경계에서 양쪽 모두 이동할 수 없으면 멈춰 사격하며, 거점 대기·폭탄 설치·해체로 전환할 때 이전 옆걸음 입력을 지웁니다. 임무 목적지가 가까운 위치로 바뀌어도 새 위치를 따라가고, 준비 중 임무 도착 뒤에는 일반 순찰로 전환하지 않습니다.
- 체력이 35% 미만이거나 탄약이 떨어지면 엄폐·후퇴·회복이 임무보다 우선합니다.
- 구역 안에서는 아군과 겹치지 않는 자리를 골라 주변을 경계하고, 조용하면 가끔 자리를 옮깁니다.

### 개인전

- 모든 참가자가 각자 한 진영입니다. 아군 합류·지원·팀 포인트가 없고, 봇 사이에도 서로 적입니다.
- 개인전 스폰 중 다른 참가자(플레이어·봇)에게서 가장 먼 곳에 나타나며, 봇마다 개인전 색 팀과 점수 행을 받습니다. 개인전 규칙에 맞춰 봇 이름표도 숨깁니다.
- 킬 +1점, 낙사·데스존 등 처치자 없는 사망 −1점은 플레이어와 같습니다. 봇이 플레이어를 처치해도 점수가 들어가며, 봇이 목표 점수에 도달하면 경기가 끝납니다.
- 시작 30초·리스폰 15초 무적 동안 봇도 투명·무음이 되고 **공격하지 않습니다**. 이 시간은 이동에 씁니다. 무적 상태인 상대는 표적으로 삼거나 추적하지 않습니다.
- 시작 무적 중 낙사하면 감점 없이 스폰으로 돌아갑니다.
- 전선이 없으므로 개인전 스폰 지점들 사이를 순찰합니다.
- 봇이 자기 장비로 스스로 죽는 경우의 감점을 피하거나, 순위에 따라 전략을 바꾸는 판단은 하지 않습니다.

<a id="mode-assault"></a>

### 이동점령

- BRAVO가 공격, ALPHA가 방어합니다. 현재 거점(A → B → C → D)이 임무이며 점령되면 다음 거점으로 넘어갑니다.
- 공격 봇은 거점으로 계속 밀고 들어갑니다. 방어팀이 거점에 있으면 점령이 멈추므로 거점 위에서 교전합니다.
- 방어 봇은 **전원** 거점을 지키며, 공격팀이 거점에 올라오면 즉시 저지·교전합니다. 45초 준비 시간에 첫 거점으로 미리 이동합니다.
- 공격 봇은 경기 시작 시 공격 출발 지점으로 이동하고, 이후 현재 거점의 공격 스폰에서 3초 저항 효과와 함께 부활합니다.
- 거점 판정은 플레이어와 같이 거점 중심에서 반경 안의 발 위치로 셉니다. 거점 반경이 작으면 방어 봇이 한곳에 모일 수 있습니다.
- (u174) 쟁탈전·이동점령 모두, 임무 점수를 소리 단서 추적보다 높게 두어 거점으로 곧장 이동합니다. 거점 안 서 있을 자리를 찾지 못하면 거점 중심으로 가고, 2블록 안에 들어오면 도착으로 보며, 막히면 다른 자리로 세 번까지 다시 시도합니다.

<a id="mode-escort"></a>

### 호위

- 움직이는 수레 주변(수레 반경)이 임무 구역입니다. 봇도 수레 판정(호위 인원 배율·저지)에 포함되며, ALPHA 봇은 수레 근처에서 회복도 받습니다.
- ALPHA(호위): 수레 곁을 지키며 밉니다. BRAVO가 붙으면 수레 옆에서 교전합니다. 연장전에서도 수레에 붙어 있으려 합니다.
- BRAVO(저지): ALPHA가 수레에 있으면 붙어서 막고, 혼자 있으면 수레를 뒤로 밀어냅니다. 마지막 체크포인트라 더 밀 수 없으면 수레 앞에서 대기합니다. 준비 시간에 수레 앞으로 미리 이동합니다.
- 리스폰 위치, 스폰 방, 스폰 출구 탐색은 체크포인트마다 바뀌는 현재 단계의 스폰을 기준으로 합니다.

<a id="mode-bomb"></a>

### 폭탄전

- 리스폰 없는 라운드제입니다. 봇도 생존자로 세어 전멸 판정에 포함되고, 라운드 중 사망하면 다음 라운드까지 참가하지 않습니다. 라운드가 시작되면 모든 봇이 체력·탄약을 채워 진영(라운드마다 공수 교대) 스폰에서 다시 시작합니다.
- 준비 시간과 라운드 종료 화면에는 움직이지 않으며, 이 사이에는 플레이어처럼 사망하지 않습니다. 방어 봇만 준비 시간에 맡은 지점으로 이동합니다. TAB 미니맵에 같은 팀 봇 위치도 표시됩니다.
- **설치:** 공격팀 플레이어가 **A 또는 B 설치 구역 위에 팀 포인트(Q)** 를 찍으면 공격 봇들이 그 지점으로 가서 설치합니다. 설치 구역 바닥에 멈춰 서서 설치 시간 동안 키를 유지하는 것과 같으며, 설치 시간·0.35블록 이동 취소·설치 가능한 바닥 판정이 플레이어와 같습니다. 한 명이 설치하면 나머지는 중단합니다. 이 포인트는 일반 팀 포인트 확인 대신 설치 명령으로 처리합니다.
- 공격팀에 살아 있는 플레이어가 없으면(봇만 남음) 봇이 라운드마다 A/B 중 한 곳을 골라 스스로 설치합니다.
- 설치 후 공격 봇은 폭탄 주변을 지킵니다.
- **해체:** 방어 봇은 설치 전에는 A/B를 나누어 지키고, 폭탄이 설치되면 그 지점을 탈환하러 갑니다. 폭탄이 손에 닿고 보이는 거리에서 **안전하다고 판단될 때만** 자동으로 해체를 시작합니다.
  - 안전 조건: 보이는 적 없음, 최근 피격 없음, 최근 3초 안에 새 적 정보 없음, 남은 폭발 시간이 해체 시간보다 김.
  - 해체 중 적이 나타나면 중단하고 교전합니다. 60% 이상 진행했으면 공격받아도 끝까지 해체합니다. 남은 시간으로 해체를 마칠 수 없으면 시도하지 않습니다.

<a id="mode-prop-hunt"></a>

### 숨바꼭질

u184부터 봇이 숨는 팀(ALPHA)과 술래(BRAVO) 어느 쪽으로든 참가합니다. 숨는 봇도 사람과 같은 블록 덱에서 뽑으므로 숨는 인원 제한(`사용 가능한 종류 수 / 3`)에 함께 셉니다. 술래는 사람이든 봇이든 한 명 이상 있어야 시작합니다. 숨바꼭질에서는 주무기·보조무기 중복 배정에 봇을 넣지 않습니다.

**술래 봇** — 어떤 블록이 플레이어인지 서버에서 받지 않습니다.

- 걸으며 앞을 훑어 진짜 블록(무작위 시선)과 우연히 눈에 들어온 변신 블록을 **같은 기준**으로 "어색한 정도"를 매깁니다. 기준은 블록 격자에서 어긋남, 공중에 뜸, 주변에 같은 블록이 없음, 트인 곳의 장식, 움직이는 걸 봄, 소리가 난 곳·자신을 다치게 한 것 근처이며, 여기에 추측을 섞습니다. 작거나 멀거나 시야 가장자리의 블록은 놓치기도 합니다.
- 기준을 넘는 블록에 산탄총 사거리까지 다가가 잠깐 망설인 뒤(애매할수록 오래) 한 발 쏩니다. 펠릿이 맞으면(플레이어가 피격 표시로 아는 것과 같음) 숨는 사람으로 알고 쫓으며 계속 쏘고, 놓치면 마지막 위치를 수색합니다. 빗나가면 그 자리를 한동안 "확인함"으로 기억합니다. 그래서 진짜 랜턴을 쏘기도 하고 잘 숨은 사람을 지나치기도 합니다.
- 시간이 지날수록, 특히 마지막 1분에는 더 쉽게 쏩니다. 경적·음악·종·폭발 같은 소리, 접촉 피해, 발사기 화살은 대략적인 위치 단서가 되어 그쪽을 수색합니다. 가끔 멈춰 주위를 둘러봅니다.
- 숨는 시간과 사망 후 5초는 사람처럼 대기실에 묶이며, 마지막 1분 이동속도 +35%도 사람과 같은 비율로 받습니다. 제트팩은 쓰지 않습니다.

**숨는 봇**

- 숨는 시간 동안 자기 블록에 맞는 자리를 점수로 고릅니다: 주변의 같은·비슷한 블록, 벽과 구석, 지붕, 어두움, 트인 시선이 적은 곳, 술래 대기실과 팀원에게서 먼 곳. 그림·표지판·횃불처럼 벽에 다는 블록은 벽에 붙어(Q) 1~2블록 위로 올라가 매달리는 자리도 고릅니다.
- 도착하면 블록 격자에 정확히 맞추고 앞면을 트인 쪽으로 돌립니다. 그림은 벽에 평평하게 붙이고, 생명력 팩·컨베이어 벨트는 바닥에 넣습니다. 바로 앞 1~3블록 턱 위의 자리는 충전 점프로 오릅니다.
- 술래가 이쪽을 보는 동안은 움직이지 않습니다. 가까이서 오래 쳐다보면 점점 불안해집니다. 맞거나 들킬 것 같으면 본 적 있는 술래에게서 멀어지고 그들이 못 보는 쪽으로, 충전 점프를 섞어 도망친 뒤 근처의 새 자리에 다시 숨습니다. 블록이 바뀌어 지금 자리와 어울리지 않으면 아무도 보지 않을 때 옮깁니다.
- 블록 기믹을 씁니다: TNT·가스통은 범위 안 술래에게 폭발, 발사기는 줄을 맞춰 화살, 엔드 수정·스포너로 공격, 차원문에 닿은 술래 날려 보내기, 자석석으로 술래에게 붙잡힌 팀원 구출, 광산 수레로 들이받고 도주, TNT 광산 수레는 TNT를 놓고 도주, 신호기는 들켜서 도망칠 때만 켜기, 커맨드 블록 비행·엔드 차원문 틀 순간이동으로 도주, 은비 인형 광선으로 보이는 술래 공격, 한비 인형은 도망칠 때 투명화.
- **조롱:** 근처 술래가 다른 곳을 보고 있을 때 경적, 소리 블록, 주크박스, 스컬크, 종, 표지판, 문·뚜껑 열고 닫기, 우는 흑요석, 세상에서 가장 예쁜 블록, 햇빛 감지기(낮/밤 전환)를 씁니다. 마지막 1분과 술래가 근처에서 엉뚱한 블록을 쏜 직후에 더 자주 합니다. 소리가 나는 조롱은 술래 봇에게 대략적인 위치를 알려 주므로 위험도 따릅니다.
- 주변에 술래가 없으면 가끔 화분 식물·모루 손상·마네킹 포즈·갑옷 거치대 등 모양을 바꿉니다. 독서대는 숨을 때 책에 한 줄을 써 둡니다.

숨는 봇의 몸은 변신 블록 크기가 되고 보이지 않으며, 총알·클릭·밀치기는 모두 변신 블록이 받습니다. 사람의 숨는 블록 피해·능력은 술래 봇에게도 똑같이 적용됩니다. 경기 중 `/gungang bot off`를 하면 남은 숨는 봇은 발견된 것으로 처리되어 경기가 끝날 수 있습니다. `/gungang bot status`에는 봇마다 `숨바꼭질 수색`, `긴가민가 62% · 조준`, `숨어 있음`, `발각 · 도주`처럼 지금 하는 일을 표시합니다.

## 봇 관전

| 관전 상황 | 봇 |
| --- | --- |
| 사망 후 리스폰 대기 | 봇에게 죽으면(총이나 봇이 던진 장비) 그 봇의 1인칭 시점 |

| 관전자·자유 관전 | 바닐라처럼 봇을 좌클릭하면 그 시점으로. 숨어 있는 봇은 클릭할 수 없음 |

## 맵 경로망: 장거리 이동·점프대·셔터

Minecraft 기본 길찾기는 수십 블록 안에서만 경로를 찾기 때문에, 왕의 길처럼 길고 구불구불한 맵에서는 상대 스폰 쪽 직선 방향의 막다른 곳에 갇힐 수 있었습니다. 이를 보완하기 위해 봇은 경기마다 **맵 전체 경로망**을 만듭니다.

- 맵의 `previewArea`(없으면 두 스폰 주변 범위)를 경기 시작 무렵부터 틱마다 몇 청크씩 나누어 한 번 스캔합니다. 보통 1~2초 안에 끝나며, 완료되면 서버 로그에 `Bot map grid ready for <맵 ID>: 크기, 점프대·셔터·스위치 수`가 남습니다. 생성 중에는 기존 방식으로 이동합니다.
- 범위가 800만 블록을 넘는 맵은 경로망을 만들지 않고(`arena too large` 로그) 기존 방식만 사용합니다. 경로망은 경기가 끝나면 지우고 다음 경기에 다시 만듭니다.
- 멀리 있는 목적지(12블록 초과)는 경로망에서 전체 경로를 계산한 뒤, 약 12칸 간격 경유점 사이만 기본 길찾기로 걷습니다. 갈 수 없는 목적지는 경로 계산 없이 바로 걸러 냅니다. 순찰 목적지도 경로망이 있으면 맵 전체 범위에서 고릅니다.
- 경로망은 한 칸 오르기, 내려가기(최대 24칸), 2~4칸 틈 점프, 낮은 난간 넘기, 수영, 점프대, 셔터를 포함합니다. 용암·불·마그마·선인장·산성·데스존 칸은 피합니다. 사다리·덩굴 오르기는 포함하지 않습니다. 경로 계산은 서버 전체에서 틱당 2회로 제한합니다.

### 과감한 낙하·난간 넘기·수영 (u174)

- 아래에 **데스존이 아닌, 밟을 수 있는 땅이나 물**이 있으면 4칸 넘는 높이에서도 뛰어내립니다. 낙하 피해를 받은 뒤에도 최대 체력의 25% 이상이 남을 때만 뛰어내리며, 물로 떨어지는 경우는 높이와 관계없이 허용합니다. 경로 비용도 낙하를 짧은 길로 평가해 계단을 빙 돌아가지 않습니다.
- 철창 같은 1칸 높이의 낮은 난간이나 얇은 벽은 넘어서 그 너머로 내려갑니다. 넘기에 실패하면 그 자리의 넘기는 잠시 쓰지 않고 다른 길을 찾습니다.
- 물속 칸을 경로망에 포함하고(머리가 물 밖에 나오는 수면), 봇이 물에 뜨도록 해 깊은 물을 헤엄쳐 건넙니다.
- 이동점령 공격팀 스폰처럼 배에서 뛰어내려 바다를 건너야 하는 구조도 이 세 가지로 빠져나옵니다(배 갑판 → 난간 넘기 → 물로 낙하 → 해변까지 수영).
- 점프대는 목적지가 멀 때 적극적으로 이용합니다. 걸어서 갈 수 있는 길보다 비행 경로가 짧으면 점프대를 탑니다.

### 점프대

- 파랑(8블록)·연두(16블록) [점프대](MOVEMENT-BLOCKS.md)마다 착지 가능한 곳을 미리 계산합니다. 착지 지점은 가로 7블록 이내, 발판 높이부터 상승 높이 이하입니다.
- 봇은 발판 중앙에 선 뒤 도약해 착지 높이를 넘을 때까지 수직으로 오르고, 그다음 착지 지점으로 수평 이동합니다. 도약 직전 실제 지형으로 궤적을 다시 확인하며, 실패한 착지 지점은 30초 동안 경로에서 제외합니다. 착지 시 낙하 피해가 없는 것은 플레이어와 같습니다.

### 셔터와 레버·버튼

- 기본 길찾기는 얇은 셔터 패널을 지나갈 수 있는 칸으로 착각했기 때문에 봇이 닫힌 셔터에 막혀 멈췄습니다. 이제 닫힌 셔터는 막힌 칸으로 처리합니다.
- 경로가 닫힌 [셔터](BLOCKS.md#shutter)를 지나야 하면, 셔터 근처(가로 8·세로 4블록 이내)의 **레버나 버튼**으로 걸어가 플레이어가 우클릭한 것과 같이 조작합니다(소리·레드스톤 동일). 이미 켜진 레버는 다른 장치를 위한 것으로 보고 건드리지 않습니다.
- 조작 후 셔터가 반응하지 않으면 레버를 원래대로 되돌리고 그 스위치는 30초 동안 다시 쓰지 않습니다. 셔터가 열리는 동안(1초당 1블록) 그 자리에서 기다립니다.
- 닿을 수 있는 스위치가 없거나, 세 번 조작해도 열리지 않거나, 10초 넘게 열리지 않으면 그 셔터 전체를 30초 동안 막힌 것으로 보고 다른 길로 돌아갑니다.
- 버튼은 신호가 짧아 높은 셔터는 끝까지 열리지 않을 수 있습니다. 봇이 지나갈 출입구에는 레버를 권장합니다.

위험물 탐색의 반복 측정 방법과 비용 비교 결과는 [봇 성능 검증](BOT-PERFORMANCE.md)에 정리되어 있습니다.

추가 서버 회귀 검증은 탐지 반경 밖 피격, 실패 목적지 재시도 제한·만료·접근 위치 변경, 지원 제보와 접촉 기억의 일치, 최신 목격 정보 우선, 광역 탐색 사이의 근거리 폭격 발견·위험물 제거를 확인합니다.

## 개발 검증

복합 상황 회귀 검증에는 체력·재장전·엄폐·방패·실패 억제가 겹친 위험 회피, 회복 이동 중 경로 예산 소진과 기존 경로 유지, 좌우 이동 앞의 알려진 트랩, 같은 X/Z의 위아래 층, 실제 발사 방향의 아군 차단을 포함합니다. 단위 테스트는 탄속·감속·낙하 추정, 무기 역할별 지점 선호, 사거리·재장전·최근 성과에 따른 장비 선택도 확인합니다. 회복팩 경로는 다른 행동과 같은 틱당 예산을 사용하며, 예산 부족은 경로 실패로 처리하지 않고 다음 틱에 재시도합니다.

`gradlew test`는 설정 범위·팀 선택·점수 규칙, 봇 프로필 DB(기존 단일 형식 읽기 포함), 행동 점수와 행동 트리, 장비 사용 점수를 검사합니다. 별도 테스트 폴더 `build/bot-smoke-run`을 준비하고 `gradlew runServer -PgungangBotSmoke`로 활 통합 테스트를 실행할 수 있습니다. 통합 테스트는 실제 서버에서 사격·이동·피해 기록, 엄폐 동작, 봇 여러 명 추가·제거·팀 지정, 스폰 게이트 탈출, 위험 지형 회피, 맵 기믹 피해, 서로 다른 팀 봇끼리의 교전을 확인합니다. 로컬 호환 JAR가 있는 환경에서는 `-PtaczVersion=1.1.8-hotfix2`를 추가해 TaCZ 실제 발사·재장전을 확인합니다. 테스트 서버는 자신만의 월드와 설정을 사용하며 완료 후 종료합니다. 테스트 코드와 테스트용 플레이어는 배포 JAR에 포함하지 않습니다.

## 닉네임·스킨·누적 전적

봇을 로비에 추가하면 팀 명단에 닉네임과 얼굴 아이콘이 표시됩니다. 이름은 입력한 그대로 표시하며 `[BOT]` 같은 접두사를 붙이지 않습니다. 경기 중 Tab 통계와 경기 결과 화면에는 같은 이름·스킨과 현재 경기의 킬/데스/어시스트/피해량이 표시됩니다. Tab 화면은 현재 경기 기록이며 누적 전적은 아래 명령으로 확인합니다. 봇은 실제 접속 계정이 아니므로 경기 밖의 바닐라 접속자 목록에는 나타나지 않습니다.

봇 1~4번은 **각자 이름·스킨·누적 전적**을 가집니다. 번호는 로비에 추가된 순서의 자리이며, 같은 번호는 항상 같은 프로필을 씁니다.

다음 명령은 OP 2 또는 서버 콘솔에서 사용합니다. 이름·스킨 변경과 프로필 재읽기는 경기 밖에서만 가능합니다. 봇 기능을 OFF로 해도 저장된 프로필과 전적은 유지되며, 로비 추가와 전투는 계속 차단됩니다.

| 명령 | 용도 |
| --- | --- |
| `/gungang bot name 1 연습봇` | 1번 봇 닉네임 변경. 공백 포함 1~24자, 입력한 그대로 표시 |
| `/gungang bot skin 2 default` | 2번 봇을 기본 Steve 스킨으로 복원 |
| `/gungang bot skin 1 file:training.png` | 서버 폴더의 스킨 파일 지정 |
| `/gungang bot skin 1 gungang:textures/bot/training.png` | 리소스팩의 스킨 지정 |
| `/gungang bot stats` / `stats 3` | 전체 또는 3번 봇의 레벨·경험치·통산 경기·승리·킬·데스·피해량·플레이 시간 조회 |
| `/gungang bot reload` | `bot-db.json`의 프로필·전적과 파일 스킨만 다시 읽기. 성능 설정 `server/bot.json`은 대상 아님 |

프로필과 전적은 실행 서버의 **`config/gungang/bot-db.json`**에 자동 생성됩니다. 봇별로 `name`, `skin`, `statistics`를 `bots` 목록에 저장하며, 봇마다 UUID가 고정되어 이름을 바꿔도 전적이 이어집니다. 1번 봇은 예전 단일 봇의 UUID를 그대로 써서, **봇이 한 명이던 시절의 파일은 1번 봇으로 그대로 읽히고 전적도 이어집니다.** 2~4번은 `Rookie 2`처럼 기본 프로필로 시작하며, 다음에 저장할 때 파일이 새 형식으로 바뀝니다.

`statistics`는 사람 DB와 같은 전적 구조이며 `experience`에 봇의 누적 경험치가 쌓입니다. 레벨은 서버의 경험치 표(`xp.json`)로 계산하며 `/gungang bot stats`에 함께 표시됩니다. 정상 경기 종료와 중단 시 실제 참여 기록이 있는 봇만 저장합니다. 매 틱 디스크에 쓰지 않습니다. 이전 저장본은 `bot-db.json.bak`에 보관합니다. 서버 프로세스가 강제 종료되면 아직 끝나지 않은 경기의 기록은 저장되지 않습니다.

[초기 JSON 예제](server-examples/config/gungang/bot-db.json)를 참고하세요. 운영 중인 DB를 이 예제로 덮어쓰면 누적 전적이 초기화되므로 기존 파일에서는 필요한 프로필 필드만 변경하세요.

`server/bot.json`은 사용 허용·팀·무기·성능·난이도 설정이고, `player-db.json`은 사람 기록입니다. 봇 기록은 별도로 보관합니다. JSON을 직접 편집할 때는 서버를 종료한 상태에서 수정하는 것을 권장합니다. 로비에서 수정했다면 `/gungang bot reload`로 반영합니다. 잘못된 파일은 덮어쓰지 않고 오류를 표시합니다.

### 커스텀 스킨 설치

공통 조건: 일반 팔 너비(Steve/wide)의 **64×64 PNG 플레이어 스킨**이어야 합니다. slim/Alex 모델과 웹 URL·계정 이름을 통한 자동 다운로드는 지원하지 않습니다.

**방법 1: 서버 폴더의 파일 (권장)**

1. 스킨 PNG를 서버의 `config/gungang/skins/` 폴더에 넣습니다. 폴더는 서버 시작 시 자동으로 만들어집니다. 파일 이름은 영문 소문자·숫자·`_`·`.`·`-`만 쓰고, 크기는 64KB 이하여야 합니다.
2. 경기 밖에서 `/gungang bot skin 1 file:training.png`처럼 실행합니다. TAB으로 폴더의 파일 목록을 볼 수 있습니다.
3. 서버가 접속한 모든 클라이언트에 이미지를 보냅니다. 리소스팩 배포가 필요 없습니다.
4. PNG를 교체했다면 `/gungang bot reload`로 다시 읽고 다시 보냅니다.

**방법 2: 리소스팩**

1. 클라이언트 리소스팩에 `assets/gungang/textures/bot/training.png`로 넣습니다. PNG를 서버의 config 폴더에만 넣어서는 이 방식으로 배포되지 않습니다.
2. 모든 참가자에게 같은 리소스팩을 적용합니다. 서버 리소스팩 배포 기능을 사용해도 됩니다.
3. 경기 밖에서 `/gungang bot skin 1 gungang:textures/bot/training.png`를 실행합니다.

로비 얼굴, 다음 경기의 봇 외형, Tab 통계에서 확인합니다. 스킨을 받지 못했거나 텍스처가 없는 클라이언트는 Steve 스킨으로 표시합니다. 기본 스킨은 추가 다운로드가 필요 없습니다. 이 변경이 포함된 동일 버전의 모드를 서버와 클라이언트 모두에 적용하세요.

### 관리자용 봇 진단

- `/gungang bot debug 1`: 1번 봇 실시간 진단을 켭니다. 관리자 권한 2 이상인 플레이어만 사용할 수 있습니다.
- `/gungang bot debug info`: 행동 점수, 위치, 현재 경로 목표, 최근 이동 계획, 경로 진행 상태, 최근 실패 이유·좌표·경과 시간을 채팅에 표시합니다.
- `/gungang bot debug off`: 진단 표시를 끕니다.

화면 하단에는 선택한 봇의 행동·경로 목표까지 거리·이동 상태·최근 실패 이유가 표시됩니다. 같은 차원 128블록 이내에서 초록 입자는 현재 경로(최대 32개 노드), 파랑은 최근 12초간 이동 위치, 노랑은 현재 경로 목표, 빨강은 최근 10초 이내의 실패 지점입니다. 색 표시는 명령을 실행한 관리자에게만 전송됩니다. 입자 설정과 지형에 따라 보이지 않을 수 있으며 상세 정보 명령은 계속 사용할 수 있습니다.

표시는 0.5초마다 갱신합니다. 리스폰하면 이전 궤적을 지우고, 경기 전환·종료에는 추적을 해제합니다. 접속 종료·관리자 권한 상실 시에도 해제합니다. 활성 사용자가 없을 때는 이동 궤적을 기록하지 않습니다. 최근 실패는 현재 정지 원인과 다를 수 있으므로 상세 정보의 경과 시간과 함께 확인하세요.

### 탐색 중 사전 엄폐
평상시 순찰 목적지는 자기 스폰 반경 8블록과 유효한 스폰 구역을 제외합니다. 스폰에 남아 있는 아군은 비전투 합류 대상으로 삼지 않습니다. 먼 목표가 막히면 주변 3·6·10·16블록의 방향별 후보를 검사해 도달 가능한 옆길을 찾으며, 벽 앞까지만 이어지는 불완전한 순찰 경로는 거절합니다. 전투 중 후퇴·회복·명시적인 팀 포인트 이동은 별도로 판단합니다.

순찰은 최근 선택한 8개 지점을 기억해 반복 이동을 줄입니다. 지점에 도착하면 상대 스폰 방향의 근거리 진입로를 가리는 엄폐물을 찾고, 2~4초 경계한 뒤 탐색을 이어갑니다. 숨은 적의 실제 위치는 사용하지 않습니다. 자기 스폰 이탈 거리(8~24블록) 이내와 스폰 구역에서는 이 행동을 하지 않으며, 교전·위험 회피·팀 포인트 등 다른 전술이 선택되면 즉시 중단합니다. 엄폐가 없으면 계속 이동하며, 탐색 비용은 기존 공용 경로 탐색 예산으로 제한합니다.

엄폐 선택은 거리 외에도 사격 가능한 모서리와 안전하게 돌아올 경로, 적 시야를 가리는 뒤쪽·대각선 퇴로를 평가합니다. 퇴로 없는 막다른 곳은 감점하며 다른 후보가 없을 때는 긴급 엄폐로 사용할 수 있습니다. 상세 평가는 가까운 후보 6개, 경로 탐색은 최대 3회로 제한합니다.

### 피격 경험에 따른 우회

봇은 자신이 적에게 피해를 입은 위치를 최대 24곳 기억합니다. 반경 6블록 안의 위치에 위험 비용을 주고, 3블록 이상 높이가 다른 층에는 적용하지 않습니다. 같은 장소에서 반복해서 맞으면 비용이 커지며 마지막 피격 후 30초 동안 점차 사라집니다. 보이지 않는 적의 정확한 위치를 이 기억에 저장하지 않습니다.

위험 비용은 순찰 목적지·엄폐 후보·실제 경로 탐색에 반영됩니다. 통행 금지가 아니므로 우회로가 없는 통로에서도 이동을 계속할 수 있습니다. 기억은 리스폰 후에도 남으며 새 경기 시작·경기 종료 시 초기화됩니다. 다른 봇과 자동 공유하지 않습니다.

스폰 이탈 중에는 스폰 구역 안의 짧은 중간 지점도 허용해 꺾인 통로를 따라 출구로 접근합니다. 스폰을 벗어난 뒤에는 다시 안으로 향하는 일반 순찰 후보를 제외합니다. 비전투 합류는 상대 스폰 방향으로 자신보다 8블록 이상 앞선 아군만 대상으로 하므로, 봇끼리 뒤따라가다가 함께 스폰으로 돌아오는 행동을 줄입니다.
