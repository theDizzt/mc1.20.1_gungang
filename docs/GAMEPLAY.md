## 로비 게임 옵션 (u145, u247 개편)

로비의 **게임 옵션**에서 관리자가 변경합니다. 적용하면 모든 참가자의 준비가 해제되며, 준비·경기 진행 중에는 변경할 수 없습니다. `config/gungang/server/option.json`의 `game`에 저장되어 재시작 후에도 유지됩니다.

u247부터 화면은 **선택한 모드의 항목 + 공통 설정**만 보여 주는 스크롤 목록입니다. 모든 칸은 선택 사항이며, **빈칸은 선택한 맵·모드의 원래 값**을 그대로 사용합니다(원래 값은 칸 안에 회색 글씨로 보입니다). 초 단위 칸 옆에는 `= 3분 30초`처럼 환산 값을 표시합니다. 모드별 설정은 서로 따로 저장되므로 한 모드를 바꿔도 다른 모드의 값은 유지되며, 실제 경기에는 진행하는 모드의 항목만 적용됩니다. **기본값** 버튼은 현재 모드 항목과 공통 설정을 비워 맵 값으로 되돌립니다. u145의 `게임 시간(분)`·`목표 점수` 두 칸은 아래 모드별 항목으로 대체되었습니다.

| 모드 | 항목 (범위) |
|---|---|
| 점령전(쟁탈전) | 게임 제한 시간(30~86400초), 준비 시간(1~600초), 점령 속도 = 중립에서 완전 점령까지 걸리는 초(1~3600), 목표 점수(1~10000) |
| 이동점령 | 제한 시간, 준비 시간, 거점별 점령 속도(A~D 각각, 1~3600초. 빈 거점은 맵 값) |
| 숨바꼭질 | 제한 시간 = 찾는 시간(60~3600초), 준비 시간 = 숨는 시간(5~600초), 제외 블록(블록 번호를 띄어쓰기·쉼표로 구분), 변신 횟수(0~50), 변신 시 블록 선택(끄기 = 무작위 / 기본 = 3개 중 선택 / 선착순), Q키로 벽에 붙기(켜기/끄기). → [숨바꼭질 옵션](PROP-HUNT.md#options) |
| 호위 | 시작 제한 시간, 준비 시간, 체크포인트 1~3 통과 후 추가 시간(각 0~3600초), 제한 시간 종료 후 추가 시간(1~600초), 수레 속도(0.1~10블록/초), 수레 최대 배속(1.00~5.00, 4명 이상일 때), 수레 후진 속도(0~10블록/초, 수비팀이 밀 때), 체크포인트 정차 시간(0~60초) |
| 폭탄전 (실험 중) | 라운드별 제한 시간(10~3600초), 준비 시간(1~600초), 라운드 수(2~99), 공수교대 라운드 수(1~라운드 수), 폭탄 설치·폭파·해체 시간(0.5~300 / 1~3600 / 0.5~300초) |
| 팀 데스매치 | 제한 시간, 준비 시간, 목표 점수(킬) |
| 개인전 | 제한 시간, 준비 시간 = 시작 무적(0~600초, 제한 시간에 포함, 제한 시간보다 짧아야 함), 리스폰 후 무적 시간(0~300초), 목표 점수 |

목표 점수 옆에는 폭탄전의 `3선승 · 동점 무승부`, 호위 최대 배속의 `2명 x1.25 · 3명 x1.50`처럼 결과를 미리 계산해 보여 줍니다. 공수교대가 라운드 수보다 크거나, 숨바꼭질 변신 횟수가 찾는 시간에 맞지 않으면 빨간 글씨로 경고하고 적용을 거부합니다.

## 쟁탈전·타이머·경기 전적

`capture.area` 안에 몸이 겹치는 살아 있는 참가자를 매 틱 판정합니다. 한 팀만 있으면 매 틱 `1 / captureStepTicks`만큼 점령이 진행되며, 기본값 2에서는 0.5%씩 증가합니다. 양 팀이 함께 있거나 아무도 없으면 즉시 멈춥니다. 이미 들어온 플레이어에게만 수평 0.15블록의 퇴장 여유를 두어 경계에서 판정이 흔들리는 현상을 줄입니다. 사망·관전·차원 이동은 즉시 제외합니다. 적 점령 게이지는 두 배 속도로 중립화합니다. 완전히 점령한 팀은 자리를 비우거나 양 팀이 함께 있어도 게이지가 깎이기 전까지 30틱(정상 TPS에서 1.5초)마다 1점을 얻습니다. 기본 100점 선취 승리입니다.

거점은 보스바 대신 상단 **공용 리본 HUD**(u216)로 표시합니다. 픽셀 계단 모양의 흰 테두리 가운데에 시계가 들어가고, 왼쪽 날개에 ALPHA, 오른쪽 날개에 BRAVO의 이름·점수·`목표 N`을 표시합니다. 점수 막대는 안쪽 끝에서 바깥으로 자라며, 방금 얻은 점수는 흰색으로 빛나고 잃은 점수는 잔상이 남았다가 사라집니다. 시계 아래에는 상태 문구(`ALPHA · 64%`, `중립`, `경합 중`)와 점령 게이지가 있습니다. u247부터 게이지는 가운데에서 양쪽으로, **점령 중인 팀의 색**으로 자라며 값이 바뀔 때 부드럽게 따라가고 변화분을 번쩍이며, 점령이 진행되는 동안 가운데에서 바깥으로 광택이 흐릅니다. 상대 팀이 넘겨받기 시작하면 게이지가 가운데부터 다시 자랍니다. 상태 글자는 ALPHA 진행이면 노랑(검은 외곽선), BRAVO 진행이면 보라(흰 외곽선), 중립·경합은 흰 글자에 검은 외곽선입니다. 색상은 `option.json`을 따르며 서버가 4틱마다 상태를 동기화합니다.

거점 범위와 그 아래 한 블록 높이에 있는 기존 양털은 완전히 점령하여 점수를 얻는 팀의 색으로 표시합니다. 기본 ALPHA는 빨강, Bravo는 파랑이며 사용자 지정 RGB는 가까운 염료 색상을 사용합니다. 부분 점령·중립화 중에는 흰색입니다. 처음 탐색한 흰색·빨간색·파란색 색유리도 동일하게 처리합니다. 준비 시작과 경기 종료 때 흰색으로 복원합니다. 다른 재질을 양털로 바꾸거나 범위 밖 블록을 변경하지 않습니다. 탐색 범위가 65,536블록을 초과하면 블록 색 변경만 생략하고 서버 로그에 이유를 남깁니다.

`timeLimitSeconds`는 0~86400초입니다. 0이면 제한 없이 경과 시간을 올려 표시하고, 양수이면 남은 시간을 내려 표시합니다. 제한시간 종료 시 점수가 높은 팀이 승리하며 동점은 무승부입니다. `capture`를 생략하면 거점 없는 시간제 경기로 사용할 수 있습니다. `/gungang stop`은 승리 팀 없이 중단 처리합니다.

타이머는 리본 가운데에 `19:24` 형식으로 표시합니다. u252부터 기본 시계는 **GUNGANG 폰트의 미래형 타이머**입니다. u269에서 설정 저장 이름을 바꿔(`lcdTimerClock`), 이전에 LCD 타이머를 저장해 둔 클라이언트도 미래형 타이머로 시작합니다. 금색으로 빛나는 숫자 아래에 얇은 스캔 선이 있고, 숫자가 바뀔 때마다 그 자리 숫자만 위에서 미끄러져 들어오며 이전 숫자는 아래로 빠집니다(짧은 RGB 분리·강조색 번쩍임, 스캔 선이 한 번 훑음). 콜론은 매초 앞 절반 동안만 켜집니다. 마지막 10초는 숫자만 크게 표시하며 호박색에서 마지막 3초는 빨강으로 바뀌고 매초 튀어나옵니다. 숫자는 가장 넓은 숫자 폭의 칸에 가운데 정렬해 시간이 흘러도 글자 위치가 흔들리지 않습니다(u247). **설정 → HUD·팀 → LCD 타이머**(`lcdTimer`, 기본 끄기)를 켜면 이전의 7세그먼트 LCD 시계를 사용합니다. LCD 시계는 `advanced_pixel_lcd-7.ttf`의 숫자와 콜론을 실제 윤곽 기준으로 중앙 정렬한 전용 텍스처이며, u247부터 꺼진 세그먼트(`8`)를 숫자 뒤에 희미하게 그려 실제 LCD처럼 보이고, `1`은 실제 LCD처럼 오른쪽 세그먼트 자리에 그립니다. LCD 시계도 10초 이하에서는 숫자만 노랑→주황 그라데이션으로 크게 나타났다가 줄어듭니다. 텍스처 재생성은 `python scripts/make_timer_atlas.py`로 수행합니다(Pillow 필요). 액션바는 바닐라 위치를 사용합니다. 30초 준비 단계에는 준비 시간이 표시됩니다. 경기 시간과 개인 플레이 시간은 준비 시간을 제외하며 서버 틱 기준입니다.

경기 중 TAB과 결과 화면의 개인 통계에는 플레이어별 K/D/A·딜량만 표시합니다. 팀 안에서는 킬 → 딜량 → 적은 데스 순으로 정렬하고 본인 행을 팀 색상으로 강조합니다. 전체 경기 시간은 결과 화면 상단에 유지하며 팀별 점수는 빨강·파랑으로 구분합니다. 개인 플레이 시간은 전적 TXT에 계속 저장합니다. 인원이 많으면 TAB을 누른 채 마우스 휠로 페이지를 넘깁니다. 적 참가자에게 실제 적용될 체력 피해를 현재 체력으로 제한하여 집계하며, 팀 피해·자해·관전자 피해·흡수 체력은 딜량에서 제외합니다. 어시스트는 사망 전 10초 안에 피해를 준 다른 적 공격자에게 부여합니다. 환경 사망은 최근 10초 안의 마지막 적 공격자를 킬로 인정합니다.

종료 시 승리/무승부/중단 화면에 개인 전적과 전체 플레이 시간을 표시합니다. UTF-8 TXT는 `config/gungang/result/날짜_시각_맵ID_UUID.txt`에 저장되어 기존 기록을 덮어쓰지 않습니다. 시작·종료 날짜와 시각(서버 시간대 및 UTC 오프셋 포함), 맵 이름·ID·설명·차원·게임 모드·제한시간, 승리 팀·점수와 개인 전적을 기록합니다. 서버 `logs/latest.log`에도 `[GunGang] MATCH START / MATCH END`로 날짜·시각·맵 정보를 남깁니다. 정상 서버 종료 시 진행 중 경기는 중단 전적으로 저장하며, 프로세스 강제 종료는 저장을 보장하지 않습니다.

## 팀 데스매치

부산(사찰), 일리오스, 리장 맵은 로비의 **맵 선택** 탭에서 맵을 고른 뒤 **쟁탈전 / 팀 데스매치**를 선택합니다. 맵·모드 변경은 관리자만 가능하며 변경 시 전원의 준비가 취소됩니다. 노르망디는 기존 전용 모드로 고정됩니다.

`config/gungang/server/option.json`에 다음 항목을 추가할 수 있습니다. 생략하면 아래 기본값을 사용합니다.

```json
"deathmatch": {
  "timeLimitSeconds": 1200,
  "winningKills": 100
}
```

설정 변경 후 로비에서 `/gungang reload`를 실행합니다. 팀 데스매치에서는 거점 점령, 거점 점수, 바닥 색 변경, 맵의 데이터팩 함수 훅을 사용하지 않습니다. 기존 팀 스폰, 30초 준비, 리스폰, 무기 선택은 동일합니다. 맵 JSON의 기존 쟁탈전 설정은 보존합니다.

먼저 목표 킬 수에 도달하면 승리하고, 시간 만료 시 킬이 많은 팀이 승리합니다. 동점은 무승부입니다. 아군 처치·자살은 킬에 합산하지 않습니다. 환경사 직전 10초 안에 적에게 피해를 받았다면 기존 전적 규칙에 따라 마지막 공격자에게 킬을 부여합니다. 나간 플레이어가 올린 팀 킬도 유지됩니다.

HUD는 쟁탈전과 같은 상단 공용 리본(u216)입니다. 왼쪽 날개에 ALPHA, 오른쪽 날개에 BRAVO의 팀 킬과 `목표 N`, 가운데에 타이머를 표시하며, 킬 막대는 목표 대비 진행도입니다. 팀 색상은 기존 `alphaColor/bravoColor`를 따릅니다.

## 이동점령

예전 이름은 **노르망디 공방전**입니다. 로비·맵 목록의 모드 이름은 **이동점령**으로 표시하며, 설정 파일과 내부 모드 ID(`normandy`, `NORMANDY`)는 호환을 위해 그대로 사용합니다. 맵 이름 "노르망디"는 지명이므로 바뀌지 않습니다. AI 봇도 참가할 수 있습니다([봇의 이동점령 규칙](BOTS.md#mode-assault)).

`config/gungang/server/maps/normandy.json`의 `enabled`를 `true`로 설정하고 `/gungang reload`를 실행하면 로비에서 선택할 수 있습니다. 모드는 이 파일을 최초 로딩 때 비활성 예제로 생성합니다. 노르망디 지형이 들어 있는 월드에서 사용하세요. 기존 파일은 덮어쓰지 않습니다.

BRAVO가 공격, ALPHA가 방어합니다. 준비 45초 동안 ALPHA는 자유롭게 이동하면서 무기를 선택할 수 있고, BRAVO는 스폰 구역에서 무기를 선택합니다. 준비가 끝나면 공격팀이 출격하며, 15분 안에 A → B → C → D를 모두 확보하면 BRAVO가 승리합니다. 시간이 끝나면 ALPHA가 승리합니다. 연장전이나 거점 점령 시 시간 추가는 없습니다.

원본 `timer:*` 데이터팩의 규칙과 좌표를 옮겼습니다. 거점 중심 반경 5블록 안에 공격팀만 있으면 매 틱 점령도가 오르며 400틱(20초)에 점령합니다. 양 팀이 있으면 정지합니다. 공격팀이 400틱 동안 없으면 이후 10틱마다 점령도 1이 감소합니다. 점령한 이전 거점은 되찾을 수 없습니다. 사망·관전자 상태는 점령에 참여하지 않습니다.

HUD는 공용 리본(u216) 아래에 A~D 네 거점의 진행 막대를 나란히 표시하고, 가운데에 `거점 B`·`경합 중`·`점령 완료` 상태와 현재 거점 점령 게이지를 표시합니다(u247부터 상태 글자·게이지 색은 쟁탈전과 같은 규칙). 활성 거점 중앙 블록은 A 파랑/B 연두/C 주황/D 빨강 색유리로 바뀌고, 그 아래 신호기와 3×3 철 블록 받침을 배치합니다. 단계 전환·경기 종료에는 변경 전 블록을 복원합니다. 복원 정보는 월드 저장 데이터에도 보관합니다. 신호기 위는 하늘까지 빛이 통하는 공간이어야 합니다. 거점 영역의 원형 입자는 중심 Y+1.2(기존보다 1블록 높게)에 표시합니다.

| 현재 거점 | 중심 좌표 | 공격팀 부활 좌표 |
|---|---|---|
| A | 17, 4, 222 | 60, 22, 163 |
| B | 6, 16, 282 | -30, 5, 197 |
| C | -25, 18, 333 | -5, 24, 259 |
| D | 40, 12, 330 | 23, 22, 258 |

거점 확보 후 살아 있는 플레이어를 강제 이동하지 않습니다. 다음 부활·도중 참가부터 새 스폰을 사용합니다. 공격팀 부활 시 원본처럼 3초 저항 보호를 적용합니다. 기존 서버 리스폰 시간, 대기 중 무기 변경, 킬러 관전과 `/gungang join BRAVO`, `/gungang stop`을 그대로 사용할 수 있습니다.

맵 JSON의 `timeLimitSeconds`는 전체 제한 시간입니다. `normandy.captureTicks`, `decayDelayTicks`, `decayStepTicks`는 점령·감소 규칙이고, `attackLaunch`는 최초 출격 위치입니다. `points`는 A~D 네 항목으로 각각 `name`, `center`, `radius`, `attackSpawn`을 지정합니다. 위치는 `x/y/z/yaw/pitch` 형식입니다. `alphaSpawn/alphaArea`는 방어팀 스폰, `bravoSpawn/bravoArea`는 공격팀 준비 구역입니다. 전투 중 공격팀 스폰 반경 4블록에서 무기를 바꿀 수 있습니다.

이동점령 맵에는 일반 쟁탈전의 `capture`를 함께 설정하지 마세요. `onPrepare/onStart/onEnd`에 기존 `timer:start`, `timer:stop` 등을 연결하거나 수동 실행하지 마세요. 경기 진행은 모드가 관리합니다. 서버와 클라이언트 모두 새 JAR를 사용하세요.

## 폭탄전과 데스존

폭탄전 맵을 선택하면 로비에서 **폭탄전 / 팀 데스매치**를 전환할 수 있습니다. `bomb` 설정이 있는 맵에서만 폭탄전을 사용할 수 있습니다. 기본 예제는 비활성화되어 있습니다. 좌표를 실제 맵에 맞게 바꾸고 `enabled: true`로 설정한 뒤 `/gungang reload`를 실행하세요.

### 라운드 규칙

- 첫 라운드의 공격팀은 ALPHA/BRAVO 중 무작위로 정하며, 이후 매 라운드 공수를 교대합니다.
- 기본 최대 5라운드, 3선승입니다. 매 라운드 25초 준비 후 210초간 진행합니다. 준비 중에는 공격팀만 공격 스폰 영역에 제한되고 방어팀은 이동할 수 있습니다.
- 폭탄·해체기 아이템은 지급하지 않습니다. **공격팀 생존자 누구나** A/B 영역 바닥에 서서 **E**(인벤토리 키)를 5초 누르면 발밑에 폭탄을 설치합니다. **방어팀 생존자 누구나** 설치된 폭탄을 4.5블록 이내에서 조준하고 E를 10초 누르면 해체합니다. E를 떼거나 0.35블록보다 멀리 움직이거나 영역·조준을 벗어나면 처음부터 다시 진행합니다. 사망해도 떨어뜨리는 장비가 없고 담당자도 없으므로 보조무기는 라운드마다 자유롭게 고를 수 있습니다.
- E는 설치·해체가 가능한 상황(A/B 영역 3블록 이내의 공격팀, 폭탄을 조준한 방어팀)에서만 가로챕니다. 그 밖에서는 기존처럼 인벤토리·무기 변경 화면을 엽니다.
- 설치 전 라운드의 공격팀이 A/B 근처에 있으면 발밑의 설치 위치를 테두리로 표시하고(가능 초록·불가 빨강), 조준점 아래에 `설치 가능 · A 지점 · E 길게 5.0초` 또는 `설치 불가 · <이유>`를 표시합니다. 이유는 `바닥에 서세요`, `물·웅덩이 위에는 설치할 수 없습니다`(물·산성액·물에 잠긴 블록·웅덩이), `위 공간이 막혀 있습니다`, `설치할 수 없는 바닥입니다`, `설치 영역 밖입니다`입니다. 방어팀이 폭탄을 조준하면 `폭탄 해체 · E 길게 10.0초`를 표시합니다. 판정은 서버 조건과 같은 계산을 사용합니다. 설치된 폭탄은 발밑에 놓이므로 충돌 판정이 없습니다(조준은 가능).
- 매 라운드 종료, 경기 종료, 새 경기 준비·시작, `/gungang reload` 실행 시 이전 버전에서 남은 폭탄·해체기 아이템이 바닥에 있으면 제거합니다.
- 설치된 폭탄은 위치에서 "삑" 소리를 내며, 가까울수록 크게 들립니다(약 24블록까지). 남은 시간이 20초 넘으면 1초, 10~20초 0.6초, 5~10초 0.35초, 5초 이하 0.2초 간격으로 빨라지고 마지막 5초는 음이 높아집니다.
- 설치 후에는 재설치할 수 없습니다. 40초가 지나면 공격팀이 승리합니다(u174 이전 45초). 폭발은 소리·입자만 재생하며 플레이어나 지형에 피해를 주지 않습니다.
- 해체가 끝나면 방어팀 승리입니다. 설치·해체 남은 시간은 기존 보조 체력바에 표시합니다.
- 설치 전에는 상대 팀 전멸로도 승리합니다. 제한시간이 먼저 끝나면 방어팀 승리입니다. 설치 후에는 라운드 제한시간과 전멸로 승패를 결정하지 않고, 폭발 또는 해체로 결정합니다.
- 사망자는 다음 라운드까지 생존한 같은 팀원(같은 팀 AI 봇 포함)의 1인칭 시점을 관전합니다. 관전 중 하단 HUD는 관전 대상의 초상화·이름·체력·손에 든 아이템을 보여 줍니다. 마우스 휠 위/아래로 이전/다음 팀원을 순환 선택하며, 관전 대상이 죽거나 접속을 종료하면 다른 생존 팀원으로 자동 전환합니다. 적이나 사망자는 선택할 수 없습니다. 팀원이 모두 사망하면 맵의 관전 위치에서 대기합니다. 다음 라운드 또는 경기 종료 시 원래 카메라 모드로 돌아옵니다. TAB을 누른 상태의 휠은 기존 점수판 페이지 전환입니다. 도중 참가자도 다음 라운드부터 플레이합니다. 매 라운드 종료 후 승리 타이틀을 3초 표시하고 다음 준비 단계로 이동합니다.
- 점수 HUD는 공용 리본(u216)입니다. 각 날개에 승리 라운드 수와 `ALPHA · ATK`/`BRAVO · DEF`, 생존 인원 표시가 붙고, 시계 아래에 `ROUND 1 / 5`를 표시합니다. 이번 라운드에 죽은 봇도 사망자로 세어 생존 인원에서 빠집니다(u219). 설치 지점에는 주황색 신호기 빔과 바닥 X가 보이며, 설치된 폭탄 위에는 `40.0초` 형식의 타이머가 표시됩니다.
- TAB을 누르면 점수판 오른쪽에 미니맵을 표시합니다. 맵에 `previewArea`가 있으면 로비 미리보기와 같은 지형 이미지를 배경으로 쓰고, 없으면 A/B 영역 주변만 그립니다. A/B 설치 영역은 주황색 영역에 검은 윤곽선을 두른 흰색 `A`/`B` 글자로, 설치된 폭탄은 빨간 점으로 표시합니다. 팀 스폰은 글자 없이 원으로만 표시합니다. **같은 팀 생존자**는 위치·바라보는 방향과 함께 팀원 고유 번호(팀 HUD·팀 포인트와 같은 번호)를 표시하며, 본인은 흰색입니다. 서버가 팀별로 자기 팀 위치만 보내므로 상대 팀은 보이지 않습니다. 지형 미리보기 이미지도 같은 표기로 다시 만듭니다(미리보기 형식 3, 서버 시작 시 자동 재생성).

### 맵 JSON

이탈리아(ID `06`)는 `bomb.areaA` / `bomb.areaB`의 직육면체 영역을 사용합니다. 각 영역은 `minX`, `minY`, `minZ`, `maxX`, `maxY`, `maxZ`로 **설치 가능한 바닥 블록의 범위**를 지정하며 양 끝을 포함합니다. Y가 같은 한 층 영역도 지원합니다. 상자·단처럼 높은 바닥에도 설치할 수 있도록 Y는 `maxY`보다 **4블록 위**까지 허용합니다(X·Z 범위와 `minY`는 그대로). 예: `minY: 12, maxY: 12`이면 Y 12~16 바닥에 설치할 수 있습니다. 허용 높이는 코드 상수 `BombRules.PLANT_ABOVE`입니다. 영역 안에서 조준한 바닥 바로 위의 빈 칸에 설치하고, 한 라운드에 폭탄 하나만 설치할 수 있습니다. 설치·해체 시간과 준비 단계 제한은 기존 규칙대로 적용합니다.

영역을 지정하면 A/B 표시는 가로 중심에 자동 배치되고 주황색 신호기 빔이 표시됩니다. 설치 후 타이머·해체·폭발 효과는 영역 중앙이 아니라 **실제 폭탄 위치**에 적용됩니다. `areaA` / `areaB`가 없으면 기존 한 블록 `pointA` / `pointB` 설정을 그대로 지원합니다.

`timeLimitSeconds`는 **각 라운드의 설치 제한시간**입니다. 기본 210초입니다. `bomb` 내부 설정은 다음과 같습니다.

| 키 | 의미 / 기본값 |
| --- | --- |
| `rounds` | 최대 라운드 수, 5. 1~99(짝수 가능). 필요한 승수는 `rounds / 2`의 정수 부분 + 1. 짝수 라운드에서 모든 라운드를 마치고 동점(예: 6라운드 3:3)이면 무승부 |
| `swapEveryRounds` | 공수 교대 간격, 1라운드 |
| `preparationSeconds` | 매 라운드 준비시간, 기본 25초 |
| `attackSpawn`, `defenseSpawn` | `x`, `y`, `z`, `yaw`, `pitch` 형태의 공격/방어 스폰 |
| `attackArea`, `defenseArea` | `minX`, `minY`, `minZ`, `maxX`, `maxY`, `maxZ` 형태의 스폰 영역 |
| `pointA`, `pointB` | 정수 `x`, `y`, `z`로 지정하는 폭탄이 놓일 한 블록 좌표 |

설치 지점은 빈 블록이어야 하며, 바로 아래에는 조준할 수 있는 바닥이 있어야 합니다. 빔/X를 표시하기 위해 기존 지형을 바꾸지 않습니다. 폭탄은 설치할 때만 실제 블록으로 배치하며, 해체·폭발·경기 중단 시 제거합니다.

폭탄전 맵에서는 기존 `alphaSpawn`/`alphaArea` 대신 `bomb.attackSpawn`/`attackArea`, `bravoSpawn`/`bravoArea` 대신 `bomb.defenseSpawn`/`defenseArea`를 사용합니다. 팀 데스매치로 전환하면 공격 스폰을 ALPHA, 방어 스폰을 BRAVO 스폰으로 사용하고 팀 데스매치의 시간·킬·리스폰 규칙을 적용합니다.

- `config/gungang/server/sub_weapons/98_bomb.json`: `id: "98"`, `plantSeconds: 5`, `fuseSeconds: 40`
- `config/gungang/server/sub_weapons/99_defuser.json`: `id: "99"`, `defuseSeconds: 10`

파일명보다 JSON의 `id`로 구분합니다. 두 ID는 설치·해체 시간 설정 전용이며 아이템으로 지급하지 않고, 플레이어의 선택 목록과 선택 요청에서도 제외됩니다. 시간 설정은 경기 시작 시 확정되며 로비에서 `/gungang reload`로 다시 읽습니다. u247부터 로비 [게임 옵션](#game-options)의 폭탄 설치·폭파·해체 시간을 입력하면 그 값이 이 파일보다 우선하며, 설치·해체 안내 문구(`E 길게 5.0초`)도 경기의 실제 값을 표시합니다. 폭탄은 `gungang:bomb`, 해체기는 `gungang:defuser`입니다. TNT/가위의 바닐라 픽셀 형태를 유지하면서 노란색/빨간색으로 바꾼 텍스처를 사용합니다.

### 모든 맵에서 사용하는 데스존

u223부터 데스존은 맵 JSON이 아니라 **데스존 영역 지정 블록**(`gungang:death_zone`)으로 지정합니다. 크리에이티브 GunGang 탭이나 `/give @s gungang:death_zone`으로 꺼내 데스존으로 쓸 칸에 설치합니다. 방벽 블록처럼 보이지 않으며, 이 블록을 손(주 손·보조 손)에 들고 있을 때만 해골 표시가 보이고 선택·파괴할 수 있습니다. 방벽과 달리 아무것도 이 블록에 부딪히지 않고 총알·클릭도 통과합니다. → [블록 설명](BLOCKS.md#death-zone)

경기 준비·진행 중 참가자(양 팀 플레이어와 AI 봇)의 몸이 이 블록 칸에 겹치면 즉시 자살 처리합니다. 관전자와 이미 리스폰/라운드 대기 중인 플레이어는 제외합니다. 준비 중에도 적용되므로 스폰 영역에 설치하지 마세요. 경기 밖에서는 작동하지 않습니다. 봇은 경로를 찾을 때 이 칸을 치명적인 지형으로 보고 피합니다.

예전 맵 JSON의 `deathZones` 배열은 더 이상 사용하지 않습니다. 기존 파일은 그대로 읽히지만 영역은 무시되므로, 필요한 곳에 블록을 다시 설치하세요. 공간마법사의 `deathzone` 저장 종류도 제거되었습니다.

자살은 사망 수만 증가시키며 적의 처치·어시스트·팀 킬 점수를 올리지 않습니다. 폭탄전은 다음 라운드까지 관전하고, 다른 모드는 기존 리스폰 대기 규칙을 따릅니다. 블록이므로 모드를 바꿔도 그대로 적용됩니다.

## 금광 호위

황금 수레는 피해를 받지 않는 맵 오브젝트입니다. 화염·용암·빙결·낙뢰·마법·폭발 피해 및 직접 적용되는 불붙음·빙결 상태를 차단하며, 투사체를 가로막는 충돌은 유지합니다.

ALPHA가 공격팀, BRAVO가 방어팀이다. 수레가 도착하면 ALPHA, 제한시간이 끝나면 BRAVO가 승리한다. 기본 제한시간은 240초다. **체크포인트 도착 즉시 180초를 추가**하고 5초간 정차한다. 정차 중에도 제한시간은 흐른다. 제한시간이 끝나면 **추가시간 5초**가 시작된다. 공격팀이 수레 옆에 있으면(밀고 있거나 방어팀과 경합 중) 추가시간이 5초로 다시 차고, 공격팀이 아무도 없으면 줄어든다. 추가시간 안에 도착점에 닿으면 ALPHA, 추가시간이 0이 되면 BRAVO 승리다. 추가시간 중 중간거점에 닿으면 보너스 시간이 더해져 일반 제한시간으로 돌아간다. HUD 중앙 시계 자리에 남은 추가시간 `4.2`와 그 아래 `추가시간`을 표시한다(2초 이하 빨강).

### 맵 설치

1. 서버 시작·설정 재로드 시 `config/gungang/server/maps/escort.json` 예제가 없으면 자동 생성된다. 또는 `docs/server-examples/escort.json`을 `config/gungang/server/maps/<id>.json`에 복사한다. 팀 스폰, 스폰 구역과 `escort.scanArea`를 실제 맵에 맞춘다. 다른 모드의 `capture`, `normandy`, `bomb` 설정은 넣지 않는다.
2. 크리에이티브의 GunGang 블록 탭에서 네 지정 블록을 꺼낸다. `/give @s gungang:escort_start` 등으로도 얻을 수 있다.
3. 평평한 지면 바로 위, 선로 중앙 높이에 빨간 시작점 → 초록 경로점들 → 노란 중간거점 1~3개 → 파란 도착점 순서로 배치한다. 시작·중간·도착 블록 자체도 경로점이다. 같은 좌표에 경로 블록을 겹쳐 놓지 않는다. 블록 X/Z 중앙이 수레의 중심이고 Y는 바퀴 바닥 높이다.
4. 다음 포인트는 현재 포인트에서 가장 가까운 미방문 블록이다. 기본 연결 거리는 16블록 이하다. 되접히는 길은 다른 구간보다 다음 포인트를 더 가깝게 배치한다. 등거리 분기, 끊긴 경로, 도착점 뒤의 남은 포인트는 오류로 처리한다. 각 구간의 높이 차이는 수평거리의 0.6배 이하여야 한다.
5. 네 종류의 블록이 모두 갖춰진 유효 경로는 편집 중에도 자동으로 폭 3블록 선로가 생성된다. 곡선과 경사에는 경로점을 추가해 모양을 조절한다. 수레가 통과할 폭 3블록·길이 5블록·높이 2.5블록의 공간과 곡선 바깥 여유 공간을 비워 둔다. 지형을 자동으로 파거나 지지대를 만들지는 않는다.
6. `enabled: true`로 저장한 뒤 `/gungang reload`, `/gungang map <id>`로 선택한다. 선택 시 JSON의 연결 거리와 검색 영역으로 다시 검증하고 선로를 생성한다. 필요하면 로비에서 `/gungang escorttrack`으로 다시 검증·생성한다. 전원 준비하면 경기 준비 단계에 들어간다.

경기 중 지정 블록은 숨겨지고 선로만 표시된다. 호위가 아닌 다른 모드의 경기 중에도 서버에 기록된 모든 호위 지정 블록을 숨기며, 종료 시 원래 상태로 다시 보인다(선로 엔티티는 그대로 둔다). 다음 중간거점은 주황색 신호기 빛으로, 모든 중간거점을 통과한 뒤에는 최종 도착점이 연두색 빛으로 표시된다. 선로는 경기 밖에서도 유지되며 일반 마인카트용 바닐라 레일과는 별개의 호위 전용 선로다.

### JSON 설정

| 항목 | 기본값 | 의미 |
|---|---:|---|
| `timeLimitSeconds` | 240 | 맵 최상위 제한시간. 생략 또는 0이면 240초 |
| `escort.scanArea` | 필수 | 지정 블록을 읽을 3차원 범위 |
| `linkDistance` | 16 | 다음 경로점 최대 거리, 1~64블록 |
| `speed` | 1 | 공격팀 1명일 때 초당 이동 블록 수 |
| `extraPlayerMultiplier` | 0.25 | u247부터 사용하지 않음(호환용으로 읽기만 함) |
| `maxMultiplier` | 1.75 | 공격팀 4명 이상일 때의 최대 배속(u247 이전 기본 2) |
| `radius` | 5 | 수레 중심으로부터 호위·저지·회복 판정 반경 |
| `checkpointStopSeconds` | 5 | 체크포인트 정차 시간 |
| `checkpointBonusSeconds` | 180 | 체크포인트 도착 즉시 추가되는 시간(왕의 길은 120) |
| `rollbackDelaySeconds` | 10 | 공격팀이 사라진 뒤 후진까지 대기 시간 |
| `rollbackSpeed` | 0.5 | 후진 속도, 블록/초 |
| `rollbackSections` | `[]` | 후진할 구간 번호. 0=시작~1거점, 1=1~2거점 또는 도착, 이후 같은 방식 |
| `healIntervalTicks` | 40 | 회복 주기. 20틱=1초 |
| `healAmount` | 1 | 주기마다 회복하는 체력 포인트 |
| `respawns` | `[]` | 체크포인트 이후 사용할 팀별 부활 위치 |

배속은 공격팀 1명일 때 x1이고, 4명(`EscortGame.FULL_SPEED_ESCORTS`)에서 `maxMultiplier`가 되도록 고르게 오르며 그 이상은 같다(u247). 기본 1.75에서는 2명 x1.25, 3명 x1.50, 4명 이상 x1.75다. 살아 있는 참가자만 계산한다. 양 팀이 함께 반경 안에 있으면 수레가 정지하고, 수비팀만 있으면 기본 속도의 **1/3**로 후진한다(u178, `EscortGame.PUSH_BACK`). u247부터 로비 게임 옵션의 `수레 후진 속도`를 입력하면 수비팀이 미는 속도를 블록/초로 지정할 수 있다. 시작 제한 시간·체크포인트별 추가 시간·연장전 길이·정차 시간도 게임 옵션에서 덮어쓸 수 있다. 아무도 없을 때의 자동 후진은 기본 속도 그대로다. 수비팀의 후진과 무인 자동 후진 모두 **가장 최근에 통과한 체크포인트까지만** 가능하며, 그 지점보다 뒤로 돌아가지 않는다. 아직 체크포인트를 통과하지 않았다면 출발점까지 후진할 수 있다. 시간 보너스는 거점마다 한 번만 지급한다. 수레 근처 공격팀은 저지·정차 중에도 회복한다.

`respawns`의 `checkpoint`는 1부터 시작한다. `alpha`, `bravo`에는 `{x,y,z,yaw,pitch}`를 넣는다. 생략한 팀은 이전 스폰을 유지하며, 변경은 이후 부활·도중 참가에 적용된다. 왕의 길(`kings-row.json`)은 체크포인트 3 항목이 없어서, 체크포인트 3을 지난 뒤에도 공격팀은 체크포인트 2 이후 스폰에서 부활한다. 활성 스폰 주변 4블록에서 장비를 선택할 수 있다.

검색 범위는 최대 200만 블록, 각 변은 X/Z 1024·Y 256블록 이하로 제한한다. 한 경로는 지정 블록 512개·실제 선로 길이 2048블록 이하다. 자동 편집 선로 연결은 기본 16블록을 사용하며, 사용자 지정 `linkDistance`는 맵 선택 또는 `/gungang escorttrack` 때 적용된다.

HUD는 공용 리본(u216) 위에 리본 폭의 연속 진행선을 그리고, 양 끝 흰 막음과 수레·체크포인트·도착점(체크무늬)을 표시한다. 왼쪽 `ALPHA · ATK` 아래는 다음 거점까지, 오른쪽 `BRAVO · DEF` 아래는 도착점까지의 **선로를 따라 남은 거리**(m)와 `체크포인트 2 / 3` 또는 `최종 목적지`다. 가운데 시계 아래에는 수레 상태 `전진 x1.50`, `후퇴 중`, `경합 중`, `정차 3.0s`, `정지`와 준비 중이면 `준비 중`을 표시한다. 시계 양옆에는 HUD 모서리 괄호가 붙어 숫자가 바뀔 때마다 바깥으로 튄다(u252).

금광 수레는 폭 3·길이 5·높이 2.5블록이다. 상단에서 서 있으면 수레 이동과 회전을 따라 이동한다. 바퀴가 회전하고 이동 중 마인카트 주행음이 재생된다. 점프하거나 내려가면 자유롭게 떨어져 나올 수 있다.

방향 전환은 경로점 사이를 부드러운 곡선으로 연결한다. 경로점 간격이 달라도 연결부의 진행 방향이 이어지고, 수레 회전은 ±180도 경계에서도 짧은 방향으로 보간한다. 급커브의 철길 조각은 더 촘촘하게 배치된다. 커브 안쪽과 바깥쪽에는 폭 3·길이 5블록 수레가 회전할 여유 공간을 둔다.

검색 영역과 체크포인트 이후 부활 위치는 [공간마법사](COMMANDS.md#area)의 `escort`, `escort_alpha`, `escort_bravo`로 등록할 수 있다.

## 인벤토리·설치물 정리와 자동 회복

경기 준비 시작, 실제 전투 시작, 경기 종료에 모든 지뢰와 방벽을 제거합니다. 로드되지 않은 청크의 설치물 기록도 무효화하여 다시 로드될 때 제거합니다. 관리자 명령 `/gungang cleardeployables`로도 전체 제거할 수 있습니다.

지뢰는 플레이어별 최대 3개(`item/landmine.json`의 `maxPlaced`로 더 낮게 제한 가능), 방벽은 플레이어별 1개(`item/barrier.json`의 `maxPlaced`로 변경 가능)입니다. 설치물 외곽선에는 설치 당시 팀 RGB 색상이 표시됩니다. 스코어보드 팀 Red는 ALPHA, Blue는 BRAVO 설정 색상을 따릅니다.

경기 준비 시작과 실제 전투 시작에는 참가자 인벤토리(방어구·보조 손·커서 포함)를 비우고 선택한 주무기·보조무기와 `server/slot9.json`의 아이템을 재지급합니다. 종료에는 인벤토리를 비우고 slot9 아이템만 지급합니다. 시작 전 아이템을 복원하지 않습니다. 엔더 상자와 월드 상자 내용은 초기화 대상이 아닙니다. 주무기/보조무기를 선택할 때도 9번 슬롯을 다시 지급합니다.

생존/모험 플레이어는 마지막 피해로부터 5초(100틱)가 지나면 체력 1을 회복하고, 이후 추가 피해가 없으면 1초(20틱)마다 1씩 회복합니다. 새 피해를 받으면 대기 시간이 다시 5초로 초기화됩니다. 흡수 체력으로 받은 피해와 직접 체력을 낮추는 처리도 대기 시간에 반영합니다. 자동 회복 타이머는 개체당 하나만 사용하며, 바닐라 허기 회복과 재생 상태 효과(포션·신호기)의 추가 회복은 중첩되지 않습니다. 회복약·체력팩·즉시 회복 포션·호위 거점의 회복은 유지합니다. 관전·리스폰 대기·크리에이티브 상태와 숨바꼭질의 숨는 팀은 자동 회복하지 않습니다. 봇도 동일한 자동 회복 규칙을 사용합니다.

허기는 게임 요소가 아닙니다. 모드가 설치된 서버에서는 모든 플레이어의 허기를 **17**, 포화도를 0으로 고정합니다(u178, `SprintStamina.FOOD`). 달리기는 허기 6 이하에서만 막히므로 항상 달릴 수 있고, 바닐라 허기 회복은 18 이상이 필요하므로 허기로는 체력이 회복되지 않습니다(`FoodRegenerationMixin`도 그대로 막습니다).

보조무기 JSON에서 `itemNbt`(별칭 `nbt`)가 생략되거나 빈 문자열/`{}`이면 `command`를 실행합니다. NBT가 있으면 아이템 지급이 우선합니다. **사용 버튼을 누를 때가 아니라 장비를 지급·재지급하거나 선택할 때** 실행됩니다. 명령은 서버 설정에 작성하며 해당 플레이어의 위치·차원·`@s`를 기준으로 권한 레벨 2로 실행합니다. 함수 호출도 가능합니다.

```json
{
  "id": "command_snowball",
  "itemNbt": "",
  "command": "item replace entity @s weapon.offhand with minecraft:snowball 1",
  "name": "명령어 눈덩이",
  "description": "명령어로 보조 손에 지급",
  "usage": "보조무기 사용 키",
  "category": "투척",
  "cooldownSeconds": 3
}
```

명령 실행 뒤 보조 손에 있는 아이템에는 기존 보조무기 수량 유지·쿨타임 설정을 적용합니다. `give`로 일반 인벤토리에 넣은 아이템까지 자동으로 보조무기로 처리하지는 않습니다. 주무기와 slot9는 `itemNbt`를 사용해야 합니다. 기존 보조무기 JSON의 빈 `command` 항목은 실행되지 않습니다.

상단 점수 HUD와 타이머는 이전의 80% 크기로 줄였으며, 다른 보스바가 없으면 상단 2 GUI 픽셀부터 배치합니다.

<a id="progression"></a>

## 누적 전적·경험치·레벨

통산 승리는 DB의 `wins`에 기록됩니다. 승리팀 참가자만 경기당 1승이 증가하며 패배·무승부·중단은 증가하지 않습니다. `/gungang stats`에 승리 횟수도 표시하고, 관리자는 `/gungang stats set <플레이어> wins <값>`으로 수정할 수 있습니다. 이전 DB에 `wins`가 없으면 0으로 읽으며 기존 전적은 유지합니다. 이전 경기의 승리 횟수를 자동으로 추정하지는 않습니다.

서버가 `config/gungang/player-db.json`을 자동 생성합니다. 별도 DB 서버가 필요 없는 UUID 기반 로컬 JSON 데이터베이스입니다. 닉네임이 바뀌어도 UUID가 같으면 기록을 유지합니다. 저장은 임시 파일을 통한 교체 방식이며 직전 데이터는 `player-db.json.bak`에 보관합니다. 손상된 DB를 빈 파일로 덮어쓰지 않습니다. DB는 서버 시작 시 다른 설정과 별도로 먼저 읽으므로, 무기·맵·`xp.json` 설정 오류로 설정 로드가 실패해도 전적·프리셋은 정상적으로 불러옵니다.

경기 종료 시 누적 경험치, 경기 참여 수, 킬, 데스, 딜량, 경기 플레이 시간(초)을 저장합니다. 경기 중 퇴장한 참가자도 포함하고 관전자는 제외합니다. `/gungang stop`과 정상 서버 종료는 진행한 전적을 저장하되 경험치를 지급하지 않습니다. 서버가 비정상 종료되면 종료하지 못한 경기의 전적은 저장되지 않습니다. 로비 대기 시간은 플레이 시간에 포함하지 않습니다.

전적 조회·수정은 [명령어 모음](COMMANDS.md#progression)을 참고하세요.

각 플레이어 기록에는 [무기 프리셋](SERVER.md#presets)도 저장합니다. `presets`는 프리셋 번호(`slot`, 1~5), 이름(`name`), 주무기·보조무기 ID(`primary`, `secondary`)의 배열이고, `defaultPreset`은 경기 시작 기본값 프리셋 번호입니다(0이면 없음).

```json
"presets": [ { "slot": 1, "name": "돌격", "primary": "ak", "secondary": "shield" } ],
"defaultPreset": 1
```

이전 버전 DB에 두 필드가 없으면 서버 시작 시 빈 값(`[]`, `0`)으로 추가해 한 번 다시 저장합니다. 경험치·전적 등 다른 값은 그대로 유지하며 변환 전 파일은 `player-db.json.bak`에 남습니다.

### 경험치 보상

`config/gungang/server/option.json`:

```json
"experience": {
  "winBase": 32,
  "winContributionMax": 24,
  "lossBase": 16,
  "lossContributionMax": 16,
  "killWeight": 1.0,
  "assistWeight": 0.5,
  "damagePerPoint": 100.0
}
```

개인 기여 점수 = 킬 × killWeight + 어시스트 × assistWeight + 딜량 ÷ damagePerPoint.
추가 XP = 기여도 최대 보상 × (개인 기여 점수 ÷ 같은 팀 전체 기여 점수), 소수점 버림.
팀 기여 점수가 0이면 추가 보상은 0입니다. 승리팀은 기본 32~56 XP, 패배팀은 16~32 XP를 받습니다. 무승부는 패배팀과 같은 보상 규칙을 적용합니다. 쟁탈전·노르망디·팀 데스매치에 공통 적용합니다.

### 레벨 요구 경험치

`config/gungang/xp.json`의 `cumulativeXp` 배열은 **91개 누적 경험치**입니다. 1레벨은 0, 2레벨은 81, 3레벨은 201, 마지막 91레벨은 267909이며 제공받은 전체 누적표를 기본값으로 사용합니다. 첫 값은 0이고 이후 값은 엄격히 증가해야 합니다. 누적 XP는 레벨업해도 차감되지 않습니다. 예를 들어 2레벨에서 XP가 141이면 현재 구간은 (141−81)/(201−81)=50%입니다.

레벨은 1~91입니다. 91레벨 이후에도 누적 XP는 저장되고 HUD 바는 가득 찬 상태를 유지합니다. 필요 경험치 표를 바꾸면 기존 누적 XP를 기준으로 레벨이 다시 계산됩니다. 로비에서 `/gungang reload`를 실행하면 적용됩니다.

커스텀 HUD는 이름 위에 레벨 엠블럼과 경험치 바를 표시합니다. 바는 해당 레벨 구간에서 다음 레벨까지의 진행률입니다. u269부터 끊김 없는 한 줄 게이지로, 테두리가 있는 어두운 트랙(u273부터 반투명이라 뒤 화면이 비침) 위에 짙은 금색에서 밝은 금색으로 이어지는 채움(윗선 하이라이트, 몇 초마다 지나가는 광택)을 그리고 10%마다 얇은 눈금(50%는 위로 더 긴 표시)을 둡니다. 경험치를 얻으면 새로 얻은 부분이 먼저 흰색으로 보이고 금색 채움이 부드럽게 따라가며, 레벨이 오르면 바가 번쩍인 뒤 0부터 다시 찹니다. 바 오른쪽 위에 `99.00%` 형식의 작은 금색 진행률 숫자를 표시하고, 최고 레벨(91)에서는 가득 찬 바와 `MAX`를 표시합니다. 서버와 클라이언트 모두 최신 모드를 사용해야 합니다.

## 개인전

개인전 전용 맵에 `freeForAll`을 설정하면 로비에서 자동으로 개인전을 선택합니다. [설정 예제](server-examples/free_for_all.json)를 참고하세요. 서버에서도 최초 로드 시 비활성 예제를 `config/gungang/server/maps/free_for_all.json`에 생성합니다. 실제 맵의 좌표로 수정하고 `enabled: true`로 바꾼 뒤 `/gungang reload`를 실행하세요.

- `freeForAll.timeLimitSeconds`: 기본 600초(10분), 30~86400초. 초반 30초도 제한 시간에 포함됩니다.
- `freeForAll.winningScore`: 기본 16점, 1~10000점.
- `freeForAll.spawns`: 1~256개의 스폰 좌표(`x/y/z/yaw/pitch`). 참가자 수 이상의 안전한 지점을 권장합니다. 무작위 후보 중 다른 생존 참가자에게서 먼 지점을 우선하며 같은 틱에 사용한 지점은 피합니다.
- `capture`, `bomb`, `normandy`, `escort`와 함께 사용할 수 없습니다. 공통 맵 형식의 `alphaSpawn/bravoSpawn/alphaArea/bravoArea`는 검증용으로 유지하며 실제 참가자 스폰은 `freeForAll.spawns`를 사용합니다.

킬은 +1점, 자살·환경사·데스존 사망은 -1점이며 음수도 가능합니다. 동점이면 현재 점수에 먼저 도달한 순서로 순위가 정해집니다. 최초 0점 동점은 참가 등록 순서입니다. 목표 점수를 먼저 달성하거나 시간이 끝났을 때 1위가 우승합니다.

경기 시작과 동시에 30초(로비 게임 옵션의 `준비 시간`으로 0~600초 변경 가능, u247) 동안 서로 보이지 않고 발소리가 나지 않으며 주무기·보조무기를 사용할 수 없습니다. 기믹 피해도 막고, 강제 사망 또는 데스존 진입 시 감점 없이 즉시 스폰을 다시 배정합니다. 이때 최초 보호 종료 시각은 연장되지 않습니다. 액션바의 **무적 활성화 중** 문구와 보조 체력바로 남은 시간을 표시합니다.

이후 사망하면 5초 동안 처치자(AI 봇 포함)를 관전하며 무기를 변경할 수 있습니다. 처치자가 없거나 관전할 수 없으면 사망 위치에서 기다립니다. 리스폰 후 일정 시간(로비 게임 옵션의 `리스폰 후 무적 시간`으로 0~300초 변경 가능, u247) 동안 본인만 다른 플레이어에게 보이지 않고 발소리와 무기 사용이 차단됩니다. 이 은신 중에도 기믹 피해와 자살 감점은 적용됩니다.

참가자는 로비에서 어느 참가 버튼을 선택해도 서로 적입니다. 경기 시작 시 빨강·주황·노랑·연두·초록·시안·파랑·남색·보라·자주·자홍·분홍·갈색·흰색·회색·검정의 색상을 무작위 배정하며, 16명까지 중복을 피하고 이후 반복합니다. 경기 결과와 저장 전적에도 개인 점수·승자를 반영합니다.

### 개인전 HUD

u216부터 팀 모드와 같은 상단 공용 리본을 사용합니다.

- **상단 HUD:** 왼쪽 날개는 나, 오른쪽 날개는 따라잡을 상대입니다. 내가 1위가 아니면 1위를, 1위이면 2위를 표시합니다. 날개마다 `1위 · 이름`과 점수, 목표 점수 대비 진행 막대를 플레이어 색으로 표시하고, 내 날개에는 상대와의 점수 차(`+3`, `±0`, `-2`)를 붙입니다. 가운데 시계 아래에 `목표 N`을 표시합니다. 관전자는 1위와 2위를 봅니다.
- **TAB 점수판·결과 화면:** 팀 카드와 같은 반투명 카드 한 장에 민트색 헤더(`개인전`, 참가 인원·총 킬·목표 점수, 오른쪽에 1위 점수)를 표시합니다. 열은 순위·얼굴·플레이어·점수·K·D·A·DMG입니다. 각 행 왼쪽에 플레이어 색 줄을 긋고 이름도 그 색으로 표시하며, 상위 3명의 순위 숫자는 금·은·동색입니다. 내 행은 내 색으로 강조하고, 인원이 많으면 휠로 페이지를 넘깁니다. 결과 화면 부제에는 우승자 이름과 점수를 함께 표시합니다.

`/gungang debug hud ffa`로 경기 없이 미리 볼 수 있습니다([디버그 명령](COMMANDS.md#debug)).
